# Research Methods Foundation

This document records the methods standards and workflow principles that should guide the Agenteer research pipeline beyond any single dataset.

## Reporting and Study Design

STROBE is the baseline reporting checklist for observational cohort, case-control, and cross-sectional studies. The pipeline should use it as a structured report QA target for observational medical analyses, especially for population definition, variables, bias, study size, statistical methods, participant flow, descriptive data, outcome data, main results, limitations, and generalizability.

TRIPOD and TRIPOD+AI are relevant when the workflow designs or evaluates diagnostic or prognostic prediction models. The pipeline should distinguish exploratory association questions from prediction-model questions because prediction work needs explicit handling of model development, validation, performance metrics, calibration, and intended clinical use.

Target trial emulation is the right framework when an observational analysis attempts a causal treatment or intervention comparison. The pipeline should require explicit target trial components before causal language is allowed: eligibility, treatment strategies, assignment, follow-up, outcomes, causal contrast, assumptions, and analysis plan.

## Dataset Fitness and Statistical Validity

Medical datasets should be evaluated for fitness for purpose before analysis. For real-world data, this means relevance to the question and reliability of key fields, timing, coding, completeness, and outcome ascertainment.

Semantic plausibility is part of dataset fitness, not just report QA. Feasibility gates, modeling plans, and standard-table execution share the same generic screen for common clinical/data variables such as age, BMI, HbA1c, blood pressure, binary flags, probabilities/propensity scores, counts, years, and length of stay. Implausible target or analysis-role values block formal planning and execution until units, coding, derivation, or column selection are repaired. Stats preflight now records this as a named `selected-variable-semantic-plausibility` gate, so impossible-value failures remain visible during run inspection instead of appearing only as a generic feasibility blocker. Nonblocking aggregate plausibility warnings still force a methods-review posture so method selection cannot silently proceed on data that looks semantically wrong.

Feasibility and direct stats preflight event support are based on analysis-complete rows when row-level data can be scanned. Local CSV/JSON feasibility scans all parsed rows for selected variables rather than only the first window of a sorted file, so events or invalid values that appear later in the table still contribute to complete-case support. Marginal outcome counts remain visible for context, but event-count, power, reviewer-risk, method-suitability, binary-model preflight, survival support, and method-decision decisions use `analysisEventCount`/`analysisNonEventCount` when covariates or design variables remove rows. Direct `stats-run` writes a marginal-versus-complete-case warning when those counts diverge and blocks binary/event-dependent inference on the analysis-complete support. This prevents an adjusted logistic, survival, prediction, or causal analysis from appearing feasible because events exist in rows that cannot actually enter the model.

Categorical method feasibility follows the same rule. Fisher exact, McNemar, and Cochran-Armitage trend checks use analysis-complete outcome and exposure levels when row-level scans are available, so a third marginal level from screened, pending, or otherwise incomplete records does not incorrectly block a valid two-by-two table. Marginal extra levels remain visible in the profile and must be reported when they reflect eligibility or ascertainment issues.

Numeric feasibility summaries preserve exact repeated-value support. Complete-case numeric shape, threshold, and domain checks use weighted value counts rather than expanded arrays, so repeated probabilities, p-values, years, times, running variables, count outcomes, and positive continuous outcomes keep their true analyzed N. This matters for temporal validation support, RDD cutoff-side counts, survival zero/negative/unique-time counts, p-value invalid-domain counts, count non-integer/negative support, and positive-GLM positivity checks. Paired-difference routing uses weighted complete-case pair-difference counts as well, so a large number of tied or zero changes cannot hide later nonzero paired differences when choosing Wilcoxon versus paired t-test evidence.

Outcome diagnostics keep compact displayed level lists for readability, but event counts and binary-support decisions are based on the full scanned level distribution. Rare positive events that fall outside the top displayed levels therefore still count toward feasibility, event-support scoring, and binary-method suitability.

Binary support requires one normalized positive/event class and one normalized negative/control class, or exactly two otherwise meaningful ordered classes with explicit weak-orientation review. Multiple same-direction labels, such as several distinct `no event` subtypes or two survival-like labels, are blocked until the endpoint is recoded or collapsed by a documented rule; they are not aggregated into a binary event definition by string prefix alone.

Binary-outcome, binary-treatment, diagnostic reference/index, and binary survival-event feasibility also distinguish raw-profile levels from analyzed levels. Logistic, propensity, diagnostic accuracy, and binary survival routes can proceed when the complete-case rows contain a valid two-level outcome/treatment/test/event indicator even if pending, unknown, indeterminate, or screened-only marginal categories appear only in incomplete rows. If the analyzed rows are not binary, the route still blocks before execution.

Variation checks are analysis-complete as well. Required analytic roles such as outcome, exposure, group, event, time, running variable, instrument, and primary analysis variables must have more than one analyzed level before the study can be treated as feasible. Constant adjustment fields are warning-level because they add no estimable information and should usually be removed or reviewed, while constant required comparison or endpoint roles block the idea before execution. Grouped numeric methods require at least two analyzed groups and analyzed outcome variation; correlation methods require analyzed variation in every requested numeric input. Marginal variation outside the complete-case rows no longer makes a degenerate group comparison, regression, causal comparison, time-to-event analysis, or correlation idea appear feasible.

Numeric domain checks now use the same analyzed-row principle. Count models check nonnegative integer-like counts in complete-case rows, positive-outcome GLMs check strictly positive complete-case outcomes, and survival methods check nonnegative analyzed follow-up time. Marginal decimal counts, zero costs, or negative follow-up times outside the analyzable rows remain data-quality context, but they do not by themselves prove that the fitted method is invalid.

Weights and count-rate offsets are validated before execution using the analyzed complete-case rows when row-level data are available. If an analysis supplies a weight column, feasibility requires numeric nonnegative weights with positive total analyzed weight; zero-weight rows and constant weights remain review warnings because they may reflect exclusions, trimming, survey design policy, or an uninformative weighting request. If a count/rate model supplies an offset/person-time column, feasibility requires numeric strictly positive analyzed offset values before the runner can use a log offset. Invalid marginal values outside analyzed rows remain visible as data-quality warnings, while nonnumeric, negative-weight, all-zero-weight, or nonpositive analyzed offset support rejects the study idea before a malformed weighted or incidence-rate model is produced.

Paired and repeated-measure feasibility now catches degenerate designs before execution without hiding method-specific diagnostics. Missing or duplicated repeated columns, nonnumeric Friedman inputs, nonbinary Cochran's Q inputs, missing clusters, and absent repeated exposure support block in preflight. Degenerate paired differences, no Friedman within-subject variation, no Cochran's Q discordance, and no long repeated-measures outcome variation are flagged before execution and then returned by the stats runner as explicit blocked method diagnostics with the method's normal QA codes. For two-column paired numeric tests, a constant baseline or follow-up column is not treated as a no-variation blocker when the paired differences themselves vary; the estimand is the within-row change distribution.

Clustered longitudinal feasibility applies the same early-rejection posture. Mixed models, GEE, binary GLMM, and repeated-measures ANOVA require an id/cluster variable with at least eight complete-case clusters and repeated complete-case observations without singleton clusters before the local route can be treated as feasible. This mirrors runner preflight and keeps one-row-per-subject tables from masquerading as longitudinal evidence.

Measurement and utility-method feasibility also checks method-specific support before execution. Kappa requires two raters/classifiers with analyzed level variation; ICC, Cronbach alpha, PCA, clustering validation, and Bland-Altman require enough varying numeric inputs; multiple-comparison correction requires numeric p-values in `[0, 1]`; and power/sample-size requires a positive effect size plus a target power strictly between zero and one.

Causal and quasi-experimental feasibility now verifies design support before execution. DiD requires binary treatment, recognizable pre/post timing, and nonempty treatment-by-period cells; event-study DiD requires treatment support in each analyzed period; interrupted time series requires numeric time plus pre/post time-point support; RDD requires a finite cutoff and enough complete-case rows on both sides; and IV requires numeric outcome/exposure variation plus analyzed instrument variation.

Missing-data method feasibility is explicit. Missingness summaries need selected variables; local MICE requires usable numeric variables with observed missingness; missingness IPW requires target missingness with enough observed rows to model observation probability; and complete-case/MNAR sensitivity routes require a numeric target plus actual missingness in the target or selected analysis variables.

Prediction-evaluation feasibility distinguishes model-score validation from binary test accuracy. The route requires a binary analyzed outcome and a numeric score with more than two complete-case values; low-resolution binary index/test columns should route to diagnostic accuracy or an association model instead of masquerading as a validated prediction score.

Regression-family feasibility now estimates model burden before execution, not only after a stats run starts. Linear, robust, quantile, penalized, logistic, multinomial/ordinal, count, and positive-outcome GLM routes approximate categorical expansion from complete-case levels, require enough complete-case rows per modeled parameter, require analyzed variation in exposure and adjustment terms, warn on sparse categorical levels, and block ordinary logistic regression when minority-class rows per parameter are too low. The same early gate also screens simple complete-case logistic separation, so a generated study plan cannot promote an adjusted logistic model when a predictor level perfectly predicts the outcome before the runner ever fits the model.

The feasibility power score uses that same modeled-term burden for regression-family methods. This keeps the top-level power/reviewer-risk explanation aligned with the actual model matrix rather than counting a many-level categorical adjustment as a single predictor.

Feasibility evidence must remain active after the first gate. Controller-generated feasibility verdicts are carried into modeling-plan artifacts and repair-time method refreshes, where warnings force explicit acceptance or repair before execution and blockers stop method selection. Direct `analysis-run` uses the same posture: a hard feasibility block stops execution before `stats-run` unless the operator explicitly requests a negative/debug run. This prevents a later planner or reviewer from treating a rejected or weakly supported study idea as ready simply because a separate method route can be named.

Identifier hygiene is a separate validity gate. Row, patient, participant, encounter, admission, stay, visit, and high-cardinality `_id` columns should be available for linkage, clustering, pairing, leakage review, and reproducibility, but they are not valid substantive outcomes, exposures, groups, covariates, or ordinary prediction features. The planning layer should block identifier-role misuse before model selection because an apparently strong association or prediction signal from an identifier is usually leakage, memorization, or a malformed design.

Outcome-leakage and post-treatment-adjustment hygiene belong at the same stage. The pipeline rejects prediction features, direct model terms, exact-match variables, instruments, grouping variables, and adjustment variables that look post-index or outcome-derived, including death dates, mortality flags, readmission/follow-up indicators, discharge disposition, length of stay, complications, endpoints, labels, and unqualified target-name derivatives. It also rejects adjustment, exact-match, weight, offset, instrument, or running-variable terms that look like post-baseline treatment, procedure, therapy, ventilation, transfusion, dialysis, catheter, or other care received unless baseline/previous/history timing is explicit. Baseline/history qualifiers can make some disease-history or prior-procedure variables valid, but the burden is on the analysis plan to prove timing before those fields are used for causal adjustment, prediction, or ordinary regression. Feasibility now catches duplicate covariates, protected role conflicts, obvious outcome-derived/post-index model terms, and obvious post-treatment adjustment terms before method execution, while direct `stats-run` preflight repeats the same shared screen so bypassing the modeling planner does not allow a leaky covariate set to fit.

Complex survey datasets require design-aware methods. For NHANES-like sources, the pipeline must track weights, strata, PSU variables, subsample weights, cycle-pooling rules, subgroup estimation constraints, and whether an analysis is only a local fixture rather than a population estimate.

Missing data should be treated as a design and reporting problem rather than a nuisance. The pipeline should require missingness summaries for population filters, exposures, outcomes, covariates, stratifiers, and weights, plus an explicit plan for complete-case analysis, imputation, inverse probability weighting, or sensitivity analysis. Ordinary fitted methods now carry this requirement too: direct stats preflight records complete-case retention and selected-variable missingness burden for every requested analysis, and QA warns when a model technically fits only after large row attrition or high variable-level missingness.

Small-cell and reliability checks should be first-class. The pipeline should flag sparse strata, unstable proportions, suppressed counts, and privacy/reliability thresholds before report generation.

## Executable Standard-Table Method Families

The local `research stats-run` route covers the major standard-table method families needed for broad biomedical and public-health research prototyping:

- core inference: independent/paired/Welch t-tests, ANOVA/ANCOVA, nonparametric group tests, categorical tests, trend tests, and correlations
- regression and GLMs: linear, robust linear, logistic, ordinal, multinomial, Poisson, negative binomial, zero-inflated counts, Gamma/inverse Gaussian GLMs, quantile, and penalized regression with inference caveats
- survival and longitudinal: Kaplan-Meier, log-rank, Cox/stratified Cox, start/stop time-varying Cox with a bounded log-time fallback, Aalen-Johansen cumulative incidence, recurrent event rates, Andersen-Gill-style recurrent-event Cox, mixed models, GEE, and repeated-measures ANOVA
- causal and quasi-experimental: propensity matching/weighting, overlap weighting, entropy balancing, AIPW, DiD/event-study scaffold, interrupted time series, regression discontinuity, instrumental variables, target-trial scaffolding, and unmeasured-confounding sensitivity
- prediction and diagnostics: local binary prediction evaluation, diagnostic accuracy, model diagnostics, calibration-related ML artifacts, and method-aware QA
- missing data and reliability: missingness summaries, MICE-style iterative imputation, missingness IPW, complete-case/MNAR sensitivity, kappa, ICC, Cronbach alpha, PCA, clustering validation, Bland-Altman, multiple-comparison correction, and power/sample-size

Execution success is not the same as scientific readiness. Methods that use bounded local approximations, such as Fine-Gray competing-risk regression, time-varying Cox without start/stop interval data, Andersen-Gill-style recurrent-event Cox without frailty/PWP confirmation, and variational-Bayes binary GLMM, emit QA warnings and should be confirmed in dedicated statistical backends before strong claims. Start/stop time-varying Cox with `--start`, `--stop`, and `--id` is now recorded as request-level executable because interval-expanded PHReg data, interval validity, subject support, and subject-clustered sandwich variance are inspectable in the packet. Recurrent-event Cox remains bounded because ordered-event, frailty, PWP, and negative-binomial recurrent-event sensitivities are still outside the local backend.

Regression-family routes write complete-case model-frame, encoded design-matrix, and prediction/fitted-value source tables in addition to coefficient and diagnostic outputs. These artifacts are part of the method contract because regression QA needs to verify which rows, encodings, fitted values, residuals, and probabilities produced the reported estimates.

Method contracts are enforced during QA as artifact requirements. The run-level `method-contract-artifact-coverage` check verifies that required files declared by the method contract are present in the artifact inventory, so a route cannot silently claim a contract while omitting required evidence tables such as `nonparametric-bootstrap.csv`, `permutation-sensitivity.csv`, fitted-value tables, or design-support tables. Required method inputs are audited too: `requiredArgumentAudit` maps contract phrases such as `time or stop`, `cluster or id`, and `running variable` to concrete stats-run request fields before a method can rely on them. Conditional file expectations such as optional robust-variance or subgroup artifacts remain visible but are not treated as universally required. `method-contract-figure-coverage` verifies that required figure families map to concrete rendered artifacts by semantic aliases. Figure source roles are also audited: `figureSourceColumnAudit` checks that every declared source role maps back to a recognized stats-run request field such as outcome, exposure, covariates, time, event, period, instrument, or running variable. `method-contract-qa-gate-coverage` verifies that declared method QA gates map to concrete emitted QA checks or explicit aliases, so a contract cannot declare a review gate such as effect size, positivity, calibration, or proportional-hazards review without leaving an inspectable QA trace. `research stats-contracts` exposes the same mappings as static `requiredArgumentAudit`, `tableArtifactAudit`, `figureAliasAudit`, `figureSourceColumnAudit`, and `qaGateAliasAudit` sections, which are the fast preflight checks for required-input, table-evidence, figure-family, source-role, and abstract-gate drift before executing expensive method smoke tests.

Method choice is an artifact, not an implicit side effect of a CLI flag. Stats preflight writes `method-decision-support.json` and a markdown companion that classify the requested method against data-shaped primary, sensitivity, and fallback candidates. This keeps the pipeline from treating a user-specified or agent-specified method as automatically preferred when the observed data shape points to Welch instead of equal-variance t-test, Mann-Whitney or Kruskal-Wallis instead of mean-scale group tests, cumulative incidence instead of ordinary Cox, penalized logistic instead of unpenalized logistic, or target-trial/propensity review before causal estimation. The request-level selector follows the same policy for generic independent two-group mean comparisons: Welch is primary only when complete-case group support and outcome shape are acceptable; Mann-Whitney becomes primary for sparse, skewed, tie-heavy, or outlier-prone two-group data; equal-variance Student t-test remains fallback unless explicitly justified. Direct `stats-run` packets, higher-level `analysis-run` packets, run inspection, and benchmarks all consume this same evidence, so a sensitivity-only or fallback-only execution cannot become `local_review_ready` by bypassing the planner.

Measurement, agreement, and exploratory routes use the same data-shaped method decision layer. Kappa records rater level support and high-cardinality warnings; ICC, Cronbach alpha, PCA, clustering, and Bland-Altman record usable and varying numeric-variable support before execution; clustering records requested `k` and complete rows per cluster; multiple-comparison correction records p-value domain support; and power/sample-size records the declared effect-size and target-power validity plus observed sample support when available. A route that can technically execute but lacks these supports is not allowed to look like a preferred primary method.

Standalone model diagnostics are also treated as a method family with their own selection evidence. The diagnostics route requires an outcome plus exposure/group term, verifies that the outcome is binary, numeric continuous, or count-like before fitting, records the inferred diagnostic family, and reports rows per modeled parameter plus binary events per modeled parameter. This lets the lifecycle distinguish a real diagnostic companion from an unsupported request against an unordered categorical outcome or a malformed model specification.

Causal and quasi-experimental routes are selected by design support rather than ordinary outcome/exposure type alone. Propensity-style methods record treatment support, semantic treated/control orientation, covariate count, treatment-model parameter burden, rows per treatment-model parameter, and minority-treatment rows per parameter. DiD and event-study routes record binary treatment support plus pre/post or period support. DiD and interrupted time-series post indicators are oriented as pre/post timing, not generic binary labels, so `pre/post`, `before/after`, and numeric `0/1` coding are accepted with explicit data-signal evidence while unknown two-level labels are blocked or sent to timing review. Interrupted time series records numeric time support and intervention coding. Regression discontinuity records running-variable support on both sides of the cutoff. Instrumental variables records instrument and exposure variation. These fields are written into method-decision `dataSignals` so a causal route cannot look preferred merely because the outcome is numeric and a model can be fit.

Propensity matching and weighting now leave method-specific design evidence beyond a treatment contrast. Matching records matched pairs, match-quality summaries, caliper-relative logit distances, matched-treated retention, and a match-distance figure. Weighting records row weights, group-level weight summaries, p95/p99/max weight evidence, effective-sample-size fraction, and a weight-distribution figure. Causal and propensity preflight scans adjustment and exact-match covariate names for obvious post-treatment, outcome, follow-up, death, readmission, or length-of-stay markers, surfaces a `no-post-treatment-adjustment` QA warning, and blocks execution when the contamination is obvious enough to be outcome-leakage rather than a review-only caution. This is a heuristic guardrail, not proof of temporality; serious causal analyses still need protocol-level time-zero and baseline-measurement review. QA checks these artifacts alongside balance, overlap, missingness, covariate timing, explicit `temporality`, explicit `unmeasured-confounding-sensitivity`, and the causal-claim boundary, because a matched or weighted estimate is not credible if it relies on poor matches, heavy weights, weak complete-case support, post-treatment adjustment, unclear time zero, or no residual-confounding sensitivity.

Instrumental-variable runs are deliberately evidence-heavy because a fitted 2SLS coefficient is not enough to justify a design. The local IV route now records the complete analysis frame, first-stage coefficients, first-stage support by instrument level or bin, first-stage observed-versus-predicted fit, partial first-stage F and partial R-squared, reduced-form coefficients, residual-inclusion endogeneity screening, and instrument-versus-covariate balance. It renders first-stage support, first-stage fit, reduced-form coefficient, and covariate-balance figures when the relevant source data exist. QA still requires explicit exclusion-restriction review and keeps the result in causal-design-review posture until instrument relevance, monotonicity, timing, and plausibility are documented outside the fitted table.

Overlap weighting and AIPW runs now leave explicit weight-stability evidence. Overlap weighting records row-level causal weights, a group-level `causal-weight-summary.csv`, propensity overlap, measured balance, and a required causal-weight distribution figure. AIPW adds row-level potential-outcome predictions, propensity scores, augmentation terms, AIPW contributions, influence values, and a component-summary table. The causal-weight and contribution-distribution figures are required diagnostics because a nominally balanced or doubly robust estimate can still be dominated by weak overlap, unstable nuisance models, or a small number of high-influence rows.

Entropy balancing now records the moment constraints directly. The route writes weighted-control versus treated-target covariate means, constraint residuals, optimizer metadata, weight distribution evidence, and required figures for both moment residuals and weights. This matters because a visually attractive Love plot is not enough; the balancing problem can be only approximately solved or can rely on a small number of highly weighted controls.

Difference-in-differences and event-study designs are treated as design-review routes, not automatic causal proof. Two-period DiD writes the treatment-by-period outcome support plus an explicit contrast summary tying raw treated/control changes to the model interaction estimate. Event-study DiD writes the interaction estimates, period support, and a non-reference pre-period screen with a dedicated figure. QA checks these artifacts, cell support, and pretrend signals while still requiring human review of parallel trends, timing, cointerventions, and treatment adoption before causal language is promoted.

Interrupted time-series runs now leave more than a segmented coefficient table. The route writes segment support, observed time-level means, fitted segmented trends, residual autocorrelation rows, and figures for observed trend, fitted trend, and residual autocorrelation. QA checks pre/post unique time-point support, HAC lag selection, fitted-trend artifacts, and serial-correlation screens so an apparent intervention effect is not promoted without inspecting time support and residual dependence.

Paired and repeated-measure runs use the same decision layer. Two paired numeric variables profile the complete-case paired-difference distribution before choosing paired t-test versus Wilcoxon signed-rank; Wilcoxon becomes primary when differences are small-sample, skewed, tie-heavy, zero-heavy, or outlier-prone. Wilcoxon now attaches row-bootstrap percentile intervals for the median paired difference and matched rank-biserial correlation and writes `nonparametric-bootstrap.csv`, so signed-rank outputs do not rely on a point estimate plus p-value alone. Independent group comparisons add deterministic label-permutation sensitivity evidence for two-group mean/rank routes and omnibus multi-group routes, preserving the model/rank p-value while making small-sample exchangeability evidence inspectable. Mann-Whitney also writes row-bootstrap percentile intervals for the median difference and rank-biserial correlation. Multi-group omnibus routes write `omnibus-effect-bootstrap.csv` with stratified row-bootstrap intervals for ANOVA/ANCOVA and Kruskal-Wallis effect sizes. More than two repeated numeric variables produce Friedman plus repeated-measures ANOVA sensitivity; Friedman reports Kendall's W and subject-row bootstrap uncertainty so the repeated-measure omnibus result has an interpretable effect-size scale. Paired/repeated binary variables produce McNemar or Cochran's Q with post-hoc/multiplicity review. Cochran's Q now reports a repeated-binary omnibus W-style effect-size scale with subject-row bootstrap uncertainty in `omnibus-effect-bootstrap.csv`, so related-proportion outputs do not stop at a chi-square p-value. McNemar uses exact binomial inference for small discordant-pair support and records when it switches to asymptotic continuity-corrected inference; it also writes `mcnemar-paired-effect.csv` with baseline/follow-up positive fractions, discordant transition counts, the paired risk difference, and a matched-pair confidence interval so paired binary reports include magnitude of change rather than only a discordance p-value. Long-form repeated-measures ANOVA writes source, within-level cell summary, sphericity, and profile-figure artifacts; duplicate subject-by-level rows are blocked and Greenhouse-Geisser correction evidence is recorded when sphericity is reviewable. These choices are recorded before execution and are audited again in `stats-qa.json`.

Categorical association runs now use complete-case joint table support during feasibility scanning. For 2x2 tables, sparse observed or expected cells make Fisher exact the primary route and demote chi-square to fallback; adequately supported 2x2 and multi-level tables keep chi-square primary with exact/trend sensitivities when appropriate. The minimum observed and expected cell support is recorded in `method-decision-support.json` so reviewers can see why the route was chosen before looking at p-values. Executed categorical routes also write `categorical-cell-diagnostics.csv` with observed counts, expected counts, Pearson and standardized residuals, per-cell chi-square contributions, zero-cell flags, and sparse expected-cell flags, so reports can explain which cells drove a global association instead of citing only a p-value. Chi-square routes now also write `categorical-permutation-sensitivity.csv`, a fixed-margin outcome-label permutation check for the global independence statistic, so sparse or multi-level tables carry a nonasymptotic sensitivity result alongside expected-cell warnings. Independent 2x2 chi-square and Fisher routes also write `categorical-effect-bootstrap.csv` with multinomial cell-count bootstrap intervals for risk difference, risk ratio, and odds ratio, giving reviewers effect-uncertainty evidence beyond asymptotic table intervals. Binary categorical labels are oriented before effect calculation using semantic event/control evidence when available, so common labels such as `dead` and `survived`, `treated` and `control`, or `event` and `no event` do not silently flip risk differences, risk ratios, or odds-ratio interpretation. QA warns when a 2x2 effect estimate falls back to lexical label order, forcing explicit exposed-level and event-level review before interpretation. Cochran-Armitage trend is allowed only when a binary outcome is paired with auditable ordered exposure evidence such as numeric ordered category codes or recognized ordinal labels; nominal multi-level categories stay on chi-square unless they are recoded by a prespecified ordered rule. Valid trend runs reindex recognized ordinal labels into semantic order, not alphabetical crosstab order, orient binary outcome labels semantically, and write `trend-support.csv` with ordered-group scores, risks, expected successes under the null, and trend components, plus `trend-effect-bootstrap.csv` with complete-case row-bootstrap intervals for the risk slope and low-to-high risk contrast. QA now checks ordering evidence, binary-outcome orientation evidence, ordered-support artifacts, and uncertainty artifacts before a trend finding can look review-ready.

Correlation runs profile complete-case numeric shape before choosing Pearson, Spearman, Kendall, or partial correlation. Pearson is primary only when the variables have enough continuous support and no obvious skew/outlier/tie burden; Spearman becomes primary for skewed or outlier-prone monotonic association questions; Kendall becomes primary for small or tie-heavy ordinal-like numeric variables. The decision artifact records complete-case N, unique counts, skewness, outlier fractions, and whether rank/Kendall routing was preferred. Executed correlation routes write source pairs, leave-one-out influence, and row-bootstrap interval artifacts; partial correlation writes the residualized values used for the adjusted correlation. This keeps correlation results from being promoted from a coefficient and p-value alone.

Count-model runs profile complete-case count distribution before choosing Poisson, negative binomial, zero-inflated Poisson, or zero-inflated negative binomial. Poisson is primary only when the outcome is nonnegative integer-valued without strong overdispersion or excess zeros; negative binomial becomes primary when variance materially exceeds the mean; zero-inflated routes become primary when zero support is high, with ZINB preferred when excess zeros and overdispersion coexist. Numeric integer support is not enough by itself: ordered score-like endpoints such as severity, grade, stage, rating, or scale variables are routed toward ordinal/multinomial methods and explicit count regression is blocked unless the variable has clear event-count semantics. The decision artifact records count N, mean, variance, variance/mean ratio, zero fraction, invalid non-integer or negative support, ordered-category evidence, and score-versus-count naming evidence. Executed count models also write observed-versus-fitted count summaries, observed-versus-expected zero diagnostics, and a binned observed-versus-fitted count figure so method review can inspect mean calibration and zero support before relying on rate-ratio estimates.

Positive continuous outcome runs profile complete-case positivity, skewness, and coefficient of variation before choosing linear regression, Gamma GLM, inverse-Gaussian GLM, robust linear, or quantile routes. Linear regression remains primary for near-symmetric positive outcomes; Gamma becomes primary when skew/CV support multiplicative mean-ratio modeling; inverse-Gaussian becomes primary only for more extreme positive-outcome skew/variation. Count-like integer outcomes route through the count-model decision layer instead. Executed Gamma and inverse-Gaussian models now leave `positive-glm-fit-summary.csv` plus a binned observed-versus-fitted figure, and QA checks that these artifacts exist before mean-ratio results are treated as reviewable.

Continuous regression runs profile outcome shape before treating ordinary least squares as the primary route. For non-count continuous outcomes, robust linear regression becomes primary when complete-case outcome values show material outlier support; quantile regression becomes primary when the outcome is strongly skewed, coarse, or tie-heavy without a stronger positive-GLM route. Ordinary linear regression remains available as a sensitivity or fallback with residual, influence, heteroskedasticity, and robust-standard-error review. Robust linear regression now leaves Huber-weight artifacts and a weight diagnostic figure, so reviewers can see which rows were downweighted and whether the route meaningfully differed from ordinary least squares. Quantile regression now leaves pinball-loss and residual-balance artifacts by fitted-value bin, so a successful median-regression coefficient is not promoted without checking whether roughly the target fraction of observations falls below the fitted quantile.

Penalized regression is treated as prediction/stability evidence, not ordinary inference. Elastic-net linear and logistic routes standardize predictors before fitting, write the feature means/scales, preserve coefficient sparsity profiles, run bounded K-fold validation when support allows it, and render coefficient and validation figures. QA keeps the penalized-inference boundary visible and requires the scaling, coefficient-profile, and validation artifacts so shrinkage coefficients cannot be promoted as classical p-values or confidence intervals.

Multi-category outcome runs profile class count, minimum class support, sparse classes, high-cardinality risk, and outcome ordering evidence before choosing ordinal versus multinomial logistic routes. Ordered numeric category codes and recognized ordered labels such as mild/moderate/severe make ordinal logistic the primary adjusted route, with multinomial as a proportional-odds sensitivity. Nominal labels make multinomial logistic primary and keep ordinal logistic fallback-only until ordering is explicitly justified. Sparse or high-cardinality class support routes first to descriptive/collapsing review. Executed ordinal logistic models leave a threshold-specific proportional-odds screen so cumulative-odds interpretation is reviewable rather than inferred from coefficient output alone. Executed multinomial logistic models now leave confusion-matrix and per-class precision/recall/F1 artifacts and figures, so reviewers can see whether sparse or clinically important classes are actually predicted before relying on class-specific contrast estimates.

Binary outcome runs distinguish prediction-score evaluation from predictor modeling before choosing a route. Numeric exposures that are probability-like or score-name-like, such as `risk_score` or `predicted_probability`, make `prediction-evaluation` the primary route for discrimination, calibration, thresholds, Brier score, and decision-curve evidence. Uncalibrated but well-resolved score-like variables can still be evaluated for discrimination, but their calibration and Brier claims are labeled accordingly. Binary or very low-resolution index variables are not treated as validated prediction scores; they are routed primarily to diagnostic/test accuracy framing, with prediction metrics only as sensitivity evidence. Numeric score shape is computed from weighted complete-case value counts, so large files with repeated probabilities retain the true analyzed N and unique-value evidence instead of inheriting an expanded-sample cap. Ordinary predictors still route to logistic-family models, with penalized logistic preferred when minority-class rows per modeled parameter are sparse. Binary outcome execution records the event orientation used for logistic, penalized logistic, prediction, diagnostic, and unmeasured-confounding routes. Semantic labels such as `dead/survived`, `event/no event`, and `treated/untreated` are oriented before estimates are interpreted; two-level labels without semantic meaning remain executable but receive a QA warning because the event or treated level is only lexical fallback.

Causal and propensity routes now record treatment-contrast orientation in diagnostics and QA. Propensity matching/weighting, overlap weighting, entropy balancing, AIPW, DiD, event-study DiD, and unmeasured-confounding sensitivity all expose which observed level is the reference/control state and which level is treated/active. This prevents a technically valid balance table, risk ratio, DiD interaction, or weighted contrast from silently describing the opposite comparison when the source data use text labels.

Estimate-table QA now treats numeric consistency as a promotion gate. The runner fails non-finite numeric fields, impossible p-values/probabilities/correlations/counts/ratios, reversed intervals, estimates outside recognized intervals, and recognized log-scale effect rows whose exponentiated odds ratios, rate ratios, mean ratios, hazard ratios, or transformed confidence intervals do not match the underlying log-scale estimates. This is intentionally stricter than manuscript wording checks because a polished table with internally contradictory estimates should not be treated as valid evidence.

Method-choice posture is enforced inside the stats packet, not only later in the analysis manifest. If data-shape decision support classifies the requested method as sensitivity, fallback, or not recommended, the run posture becomes exploratory method-choice evidence even when the run is otherwise bound to a spec. This prevents a governed-but-suboptimal route from looking like the primary analysis simply because it produced tables.

Analysis-manifest readiness now consumes stats QA status directly. A run directory with `stats-qa.json` present but failing is blocked rather than treated as artifact-complete. Missing or unreadable stats QA is also blocked; warning-level QA stays visible as review evidence rather than being collapsed into a file-exists check.

Methods-aware QA consumes the same stats QA evidence. A failed, missing, or unreadable stats QA artifact creates a blocker-level `stats-qa-readiness` check, so manuscript, inspection, benchmark, and method-review commands do not disagree about whether a run can be promoted.

Methods-aware QA also consumes method-selection evidence directly. A blocked method decision creates a blocker-level `method-decision-readiness` check. Missing, fallback-only, sensitivity-only, or not-recommended decisions produce a methods-review warning even if the model fit and stats QA passed. This keeps the reviewer-facing lifecycle from confusing "a method executed" with "the data-shaped primary method was used."

Unified run inspection surfaces the same method-decision status and method-decision consistency beside method QA and stats QA. Operators should be able to see, in one report, whether the selected route was preferred, fallback-only, sensitivity-only, blocked, missing decision evidence, or backed by contradictory decision artifacts. When there is no manifest yet, methods-aware QA prefers method-decision evidence embedded in the executed `stats-run.json` before sidecar files, so a stale or manually repaired sidecar cannot override the decision tied to the fitted result. It also compares manifest, embedded, sidecar, and preflight method-decision evidence when multiple sources exist; contradictory method, role, verdict, or primary-method evidence creates a methods-review warning. Analysis manifests and benchmarks now carry the same consistency posture, so contradictory method-decision artifacts keep a stats packet exploratory even when the chosen source says the route was preferred.

Prediction validation provenance is now explicit. `prediction-evaluation` writes `prediction-validation-split.csv` for every run and records whether the estimate is apparent/local, external-or-holdout by `--validation-column/--validation-value`, or temporal by `--validation-time/--validation-cutoff`. Apparent runs warn because they evaluate all complete rows. Temporal and external/holdout runs record evaluated rows, non-evaluated development/reference rows, event/non-event support in the evaluation split, score range, and time range where applicable; preflight blocks validation splits that do not contain both outcome classes because ROC, PR, calibration, and threshold metrics would be invalid. QA checks the validation design and split artifact before prediction claims can be promoted beyond local apparent performance. When `--id` is supplied, `prediction-validation-subjects.csv` records each subject's evaluation/development membership and QA fails held-out or temporal validation claims if any subject appears on both sides of the split. Analysis manifests and benchmarks now treat unresolved prediction validation-design warnings, missing subject-level leakage auditability, weak event/non-event support, non-probability score boundaries, unstable bootstrap uncertainty, and requested subgroup instability as critical stats-QA warnings, so a prediction packet cannot become local-review-ready solely because AUROC, PR, or calibration tables exist.

Independent group comparisons profile complete-case outcome shape and per-group support before choosing parametric versus rank-based routes. Group-method eligibility is based on analytic complete-case group levels, not marginal dataset levels, so a group with no analyzable outcome rows does not incorrectly turn a two-group comparison into a three-group problem. The decision artifact records complete-case N, group count, minimum group size, outcome unique count, skewness, outlier fraction, and whether rank routing was preferred. Two-group comparisons choose Welch only when shape/support are acceptable and Mann-Whitney when support is sparse, skewed, tie-heavy, or outlier-prone. Directional two-group estimates orient common semantic labels before reporting `group_b - group_a`, so labels such as `exposed/unexposed`, `case/control`, or `treated/untreated` do not flip mean differences, median differences, or rank-biserial signs by row order. QA warns when a two-group comparison falls back to lexical label order and requires explicit reference/comparison review before directional interpretation. Multi-group comparisons choose ANOVA only when shape/support are acceptable and Kruskal-Wallis when rank-based omnibus evidence is safer. Adjusted group comparisons keep ANCOVA as the primary adjusted route but add unadjusted rank, robust-linear, and quantile sensitivities when the observed outcome shape makes mean-scale claims fragile.

Omnibus core-inference routes are expected to leave interpretable effect-size, interval, and follow-up evidence, not only a global p-value. ANOVA/ANCOVA estimate eta-squared, partial eta-squared, and omega-squared where model support permits; Kruskal-Wallis reports epsilon-squared; Friedman reports Kendall's W; Cochran's Q reports a repeated-binary W-style effect-size scale. These routes write `omnibus-effect-bootstrap.csv` for effect-size uncertainty when support permits. ANOVA, ANCOVA, Kruskal-Wallis, Friedman, and Cochran's Q write Holm-adjusted `posthoc-contrasts.csv` artifacts when pairwise interpretation is applicable, and QA warns when a report tries to make pairwise claims without those multiplicity-controlled source tables.

Reliability and agreement routes report uncertainty, not only point estimates. Cohen's kappa includes an approximate confidence interval. ICC and Cronbach alpha use bounded row-bootstrap percentile intervals, write `reliability-bootstrap.csv`, and add QA checks for bootstrap support so scale reliability cannot be promoted from a single unsupported point estimate.

Power/sample-size review should be tied to observed data support when a dataset is already available. The local route records the required sample size for the declared effect size and target power, then compares it with observed nonmissing rows for the supplied variable. Binary outcomes also record event and non-event support so large but low-event datasets are not treated as adequately powered for adjusted modeling.

Causal sensitivity routes must not stop at a point estimate. Unmeasured-confounding sensitivity records the observed binary risk ratio, a confidence interval, a point E-value, and the confidence-limit E-value closest to the null, plus a source table of treated/control event counts. The QA posture remains cautionary because E-values quantify how strong residual confounding would need to be; they do not validate exchangeability or replace design review.

Regression discontinuity runs are required to show design support around the cutoff, not only a discontinuity coefficient. The local route uses a side-specific local-linear specification, writes running-variable support, row-level fitted values, bandwidth-sensitivity, cutoff-density, and covariate-continuity artifacts, and QA-checks whether supported bandwidth windows, manipulation screens, fitted-value provenance, and baseline covariate jump screens are available before any causal interpretation.

Missing-data sensitivity should be inspectable before a manuscript claims that complete-case or available-case evidence is stable. Method decision support now treats missingness-summary as the primary first route, then selects MICE, missingness IPW, complete-case sensitivity, or MNAR sensitivity only when observed missingness and predictor support make those routes meaningful. Missingness IPW records a promoted weight artifact plus support, weight stability, effective sample-size QA, and a weight-distribution figure. Complete-case and MNAR routes write a scenario table and figure, record the range of scenario means, and QA-check whether missingness assumptions materially shift the outcome estimate.

Competing-risk event coding is a planning guardrail, not just a runner detail. Multistate event variables should trigger cumulative-incidence review first; ordinary Cox, Kaplan-Meier, or log-rank routes require a reviewed event-of-interest recode and an explicit statement about how competing events are handled.

Aalen-Johansen cumulative-incidence runs now leave horizon-level competing-risk support evidence. In addition to the CIF curve and optional final-CIF group contrasts, the route writes `cumulative-incidence-horizon-summary.csv` and a matching figure. The source table records at-risk rows, target events, competing events, all events, censoring, cumulative incidence, and event fractions at data-supported horizons, which makes time-horizon event-count reporting reviewable before a manuscript claims 1-, 3-, 5-, or similar follow-up differences.

Fine-Gray competing-risk regression is now executable as bounded methods-review evidence instead of being a hard backend block. The route fits a local subdistribution partial-likelihood approximation with competing events retained in risk sets, writes `fine-gray-model-frame.csv`, `fine-gray-design-matrix.csv`, `fine-gray-risk-sets.csv`, `fine-gray-baseline-subdistribution.csv`, `fine-gray-predictions.csv`, and `cumulative-incidence.csv`, and renders subdistribution hazard-ratio, baseline CIF, and Aalen-Johansen context figures. QA requires convergence/rank evidence, risk-set support, competing-event accounting, artifact completeness, and a visible approximation warning because IPCW censoring weights and confirmatory subdistribution-hazard inference still require R `cmprsk`/`riskRegression` or another validated backend.

Binary time-to-event runs profile total event count, censoring count, unique time support, zero-time rows, grouped event support, and events per modeled predictor before choosing survival routes. Event indicators use the same semantic binary orientation policy as binary models, so labels such as `dead/alive`, `event/no event`, and `detected/not detected` are counted correctly before grouped log-rank or Cox support is assessed. Ambiguous two-level event labels remain executable but receive an orientation warning. Kaplan-Meier/risk-table review stays primary when grouped comparisons have zero-event or sparse-event groups. Log-rank becomes primary only when every comparison group has adequate event support. Cox regression becomes primary only when event-per-predictor support is adequate; otherwise it is treated as sensitivity evidence until the model is simplified or more events are available.

Kaplan-Meier and log-rank execution now includes restricted mean survival time evidence. Each run writes `survival-rmst.csv` and `survival-rmst.png` using a common data-supported `tau`, bootstrap percentile intervals, and pairwise RMST differences when groups are present. This gives reviewers an interpretable time-horizon survival summary alongside curves, risk tables, and log-rank p-values instead of forcing every survival comparison through a proportional-hazards interpretation.

Cox execution records provenance and fitted-risk artifacts in addition to hazard ratios. Each Cox-style run writes `cox-model-frame.csv`, `cox-design-matrix.csv`, `cox-risk-scores.csv`, and `cox-risk-strata.csv`, plus a `cox-risk-scores.png` distribution figure. These artifacts make the complete-case frame, categorical expansion, linear predictor, relative hazards, Harrell C-index context, and event fraction by fitted-risk stratum reviewable before a manuscript treats the hazard-ratio table as stable adjusted evidence.

Mixed-model, GEE, and binary GLMM execution use the same provenance posture. Each fitted route writes `longitudinal-model-frame.csv`, `longitudinal-design-matrix.csv`, `longitudinal-fitted-values.csv`, and `longitudinal-cluster-residuals.csv`, plus an observed-versus-fitted figure. Binary GLMM runs also write `glmm-random-effects.csv` and `glmm-cluster-calibration.csv` with matching figures, so reviewers can inspect random-intercept spread and cluster-level event-rate calibration. These artifacts let QA verify which complete-case rows and encoded predictors produced the estimates, whether residuals cluster by subject, and whether a converged or approximated longitudinal coefficient table is hiding poor fit or implausible fitted values.

Method selection now recognizes declared repeated structure. If a request includes a supported subject/cluster identifier with repeated complete-case rows, the data-shaped decision artifact ranks mixed models and/or GEE ahead of ordinary regression instead of treating the clustered route as an unrelated manual override. Weak-but-executable cluster support remains a lifecycle-critical warning, so a model can be correctly selected and still require additional support or justification before promotion.

Recurrent-event rates are treated as bounded descriptive incidence evidence unless a dedicated recurrent-event backend is used. The local rate route writes group-rate, subject-summary, and rate-ratio contrast tables, checks person-time and subject support, screens subject-level event-count overdispersion, and warns that aggregate Poisson rates do not replace recurrent-event models. The local `recurrent-event-cox` route fits an Andersen-Gill-style start/stop PHReg model from interval-expanded rows, writes recurrent-event interval, subject-burden, and `cox-cluster-robust-variance.csv` artifacts, renders hazard-ratio, interval-support, subject-event, and risk-score figures, and QA-checks recurrent-event burden, interval validity, and cluster-robust variance. It still carries a model-boundary warning because frailty, ordered-event PWP, and negative-binomial recurrent-event inference are not implemented in the local backend.

Every stats run should leave behind a machine-readable estimate table, diagnostics, QA, and a figure manifest. Figures are part of the evidence packet, not decoration: captions, source columns, source-data CSVs, render QA, and required figure-family coverage should travel with the report. Required figure coverage is semantic rather than filename-only, so a method contract can require a hazard-ratio forest, risk table, Love plot, or residual diagnostic while the concrete runner artifact remains method-specific. Lifecycle readiness consumes that evidence too: warning-level visual QA for a missing figure manifest, required figure coverage, or rendered figure quality prevents `local_review_ready` until the visual evidence is repaired or rerun. The same lifecycle gate treats unresolved semantic plausibility, complete-case attrition, selected-variable missingness, weak sample/event support, survival/competing-risk/recurrent-event warnings for censoring context, RMST/CIF horizon support, proportional-hazards diagnostics, competing-event accounting, risk-set support, recurrent-event burden, and longitudinal/repeated-measures warnings for cluster support, residual/fitted-value evidence, GLMM calibration/optimization, and sphericity as critical. Core inference, categorical, and correlation warnings for missing effect sizes, interval evidence, bootstrap/permutation sensitivity, sparse cells, trend/order orientation, post-hoc contrasts, source artifacts, normality/variance review, or influence sensitivity are also critical because a p-value without effect-size, uncertainty, and support context is not a complete analysis packet. Regression/GLM warnings for model burden, collinearity, influence, residual shape, heteroskedasticity, separation, binary class balance/orientation, count overdispersion/offset support, positive-outcome GLM support, penalized-model inference/validation provenance, diagnostic orientation/precision/sparse-cell warnings, prediction validation/leakage/support warnings, non-probability score-boundary warnings, and unstable prediction bootstrap/slice evidence are lifecycle-critical. Causal and quasi-experimental warnings are critical too: treatment/time orientation, temporality, post-treatment adjustment, residual-confounding sensitivity, propensity/causal overlap and effective sample size, match retention/distance, weight-tail instability, DiD parallel-trends/pretrend review, ITS autocorrelation, RDD density/continuity, IV first-stage/exclusion/balance evidence, target-trial gaps, and AIPW/entropy artifacts must be repaired or explicitly justified before local-review readiness. Missing-data, reliability/agreement, PCA/clustering, multiple-comparison, and power warnings for weak mechanism screens, incomplete imputation variability/distribution evidence, unstable missingness IPW, missing reliability uncertainty, proportional bias, weak explained variance or cluster metrics, missing adjusted-p-value artifacts, or observed sample/event support below the declared target also keep the packet exploratory. A model that technically fits on implausible units/coding, after large row loss, with weak inferential support, unstable coefficient diagnostics, weak survival/longitudinal support, unstable diagnostic cells, unsupported prediction-validation provenance, unresolved causal-design evidence, or incomplete missingness/measurement support needs data repair, missingness review, sensitivity analysis, redesign, held-out/temporal validation, leakage audit evidence, or a justified support plan before local-review readiness.

The manifest stores this distinction explicitly. `qaReadiness.warningChecks` lists every warning-level QA check, `criticalWarningChecks` contains the subset that blocks promotion, `advisoryWarningChecks` contains warnings that should be reviewed but do not by themselves prevent local-review readiness, and `warningCounts` summarizes total, critical, and advisory warning counts. This makes runner/controller repair loops deterministic: they can repair critical warnings first and still preserve advisory context for the human methods review.

The `research stats-contracts` command also reports local runner capability for each method. A method contract can be `executable`, `bounded_approximation`, or `backend_blocked`; downstream planners and reviewers should treat bounded or blocked methods as requiring follow-up backend validation or redesign before strong claims. The same capability status is written into every `stats-run.json`, `method-contract.json`, stats report, and QA file so packet inspection does not depend on re-running the planner. Capability is request-aware where the data roles change what the runner can actually support: for example, `time-varying-cox` remains bounded as a generic method contract, but a run with declared `start`, `stop`, and `id` interval columns records the interval-expanded route as executable and QA checks that this request-specific capability was recorded correctly. The lifecycle layer consumes the same field: bounded methods are held at methods-review/exploratory readiness, and backend-blocked methods remain blocked until rerouted.

## Provenance and Reproducibility

FAIR principles push the workflow toward machine-actionable metadata for finding, accessing, interoperating with, and reusing datasets and artifacts.

RO-Crate is a strong fit for reproducible research packet export because it packages data, code, workflow files, outputs, and metadata into a structured research object.

W3C PROV gives Agenteer a general model for entities, activities, and agents. The research packet should evolve toward provenance records that connect prompts, validations, approvals, commands, inputs, generated code, outputs, and human-in-the-loop judgments.

## Agenteer Product Implications

The orchestrating agent should remain part of each stage. Automation should not hide the decision boundaries; it should make them inspectable.

The CLI should expose structured state for every boundary:

- pipeline shape
- packet checkpoint
- loop status
- packet summary
- methodology validation
- data quality profile
- runner contract
- artifact/provenance graph

Each structured output should have a schema version and stable field names so future nodes can compose and mutate the workflow safely.
