## First-Principles Re-Derivation

Desired end-to-end dogfood outcome:

1. A user gives a dataset-grounded research question.
2. The pipeline builds a local packet that can rerun against actual data.
3. The pipeline produces a shareable packet that does not disclose local environment paths.
4. The packet records what was derived from what.
5. The packet can be inspected by an agent or human for scientific limits, not only file integrity.

Smallest architecture that supports this:

- Local packet: may contain absolute local paths for rerunability.
- Shareable export: must contain only relative refs, source refs, hashes, package/runtime facts, and derived-redacted evidence.
- Export receipt: must scan copied artifacts and fail if local paths leak.
- Actual-data loop: must not stop at packaging; it must return to cohort scouting, semantic quality, and real execution pressure.

## Diff Against Current Reality

- Present: local packet now has `data-access.json`, `data-access-redacted.json`, readiness, and export receipt.
- Gap: export still copies raw path-bearing artifacts and path-bearing packet metadata.
- Gap: there is no artifact-class registry to decide local-only versus shareable.
- Gap: actual-data work has one main HbA1c/diabetes packet; we need a second domain question soon.

## Smallest Correction

Next implementation should not chase full archive formats. It should add one artifact-class policy:

- `data-access.json`: local-only
- `data-access-redacted.json`: shareable replacement
- `export-summary.json`: shareable receipt
- path-bearing operational packet metadata: either sanitize or exclude from share scan until sanitized

After that, pivot to a second actual NHANES research question.
