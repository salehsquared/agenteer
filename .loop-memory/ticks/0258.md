# Tick 0258 - Question The Question - Taxonomy Auditability

## Scope

Label: `methods`, `QA`, `architecture`.

Question: should exploration now test a second outcome, or first make the new taxonomy auditable?

Decision: auditability comes first. A second outcome would multiply opaque classifications if the system cannot explain why each category and score was assigned.

## Hypothesis

If candidate taxonomy becomes versioned and evidence-bearing, exploration can safely expand to more outcomes later because reviewers can inspect rule ids, score adjustments, and primary-use recommendations.

## Intervention

- Added `primaryQuestionUse`: `recommended`, `review_before_primary`, or `avoid_primary`.
- Added `taxonomyEvidence` with:
  - `taxonomyVersion`
  - `matchedRuleIds`
  - `matchedTerms`
  - `scoreAdjustments`
  - `rejectedCategories`
- Added a deterministic `taxonomy-evidence` QA check.
- Carried taxonomy evidence through `explore-promote` into `modelingPlanSeed`.
- Updated docs and tests.
- Regenerated the actual NHANES exploration, handoff, and modeling-plan artifacts.
