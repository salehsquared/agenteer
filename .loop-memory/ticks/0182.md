# Tick 182 - web-search - calibration evidence for ML runs

## Axis

Web-search / methods / QA.

## Hypothesis

If binary clinical prediction runs persist calibration evidence, Agenteer will be closer to trustworthy research ML because discrimination metrics alone are insufficient for clinical prediction review.

## Sources

- TRIPOD+AI 2024 says clinical prediction model reports should evaluate predictive accuracy with discrimination, calibration, and clinical utility: https://www.bmj.com/content/385/bmj-2023-078378
- scikit-learn's probability calibration documentation describes calibration curves/reliability diagrams and notes Brier/log loss as proper scoring rules: https://scikit-learn.org/stable/modules/calibration.html
- Adaptive sample-size work for clinical prediction emphasizes overfitting, calibration slope, optimism, and sufficient events/predictor-parameter pressure: https://link.springer.com/article/10.1186/s41512-021-00096-5

## Deliverable

Added persisted binary calibration evidence to the sklearn ML runner:

- `calibration.csv` for binary probabilistic classifiers
- `calibration_bins` metric
- `calibration` artifact kind
- tests requiring calibration output from binary classification
- docs describing the calibration artifact

## Counter-Design Rejected

I rejected only documenting that users should check calibration. The runner already has predicted probabilities; it should persist calibration evidence by default for binary clinical prediction.

## Promotion Decision

Promote. Calibration is now part of the default binary ML artifact contract.

## Remaining Doubt

This is calibration-curve evidence, not full clinical utility. Decision curves/net benefit remain a later evaluator.
