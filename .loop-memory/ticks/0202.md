# Tick 0202 - Add Primitive / Reproducibility

## Hypothesis

Stats and ML run directories need one compact manifest so route, posture, artifact completeness, hashes, and readiness can be inspected without reading every file.

## Scope

- Add a manifest primitive for existing `stats-run` and `ml-run` outputs.
- Keep it post-run and generic; do not pretend every analysis run is a paper packet.
- Wire it through CLI, exports, tests, and docs.

## Intervention

Added `research analysis-manifest --run-dir <dir> [--out <path>] [--json]`.

The manifest records:

- run kind: stats or ML
- run id/status
- method or model
- typed result posture
- readiness: `local_review_ready`, `exploratory_only`, or `blocked`
- artifact completeness and missing required artifacts
- artifact hashes
- issue codes
- next action

## Decision

Keep `analysis-manifest` as the compact non-paper packet primitive. It makes stats/ML runs inspectable without overloading paper lifecycle semantics.

## Counter-Design Considered

Rejected expanding `paper-lifecycle` to pretend every stats/ML run is a paper. A compact analysis-run manifest is the smaller primitive for non-paper routes.
