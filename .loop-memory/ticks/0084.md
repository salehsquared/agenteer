## Findings

- W3C PROV frames provenance as information about entities, activities, and agents involved in producing data, used to assess quality, reliability, and trustworthiness. Applicability: Agenteer's real-data evidence should distinguish the Parquet file entity from the table-summary activity and runtime agent. Source: https://www.w3.org/TR/prov-overview/
- RO-Crate describes research data and contextual entities in JSON-LD; it explicitly supports file-level metadata and provenance about how files were created using software/equipment. Applicability: `data-access.json` can stay simple now but should align with the same shape: files as data entities, runtime/software as contextual entities, summaries as generated evidence. Source: https://www.researchobject.org/ro-crate/specification/1.1/introduction.html
- Workflow Run RO-Crate captures workflow execution provenance at multiple granularities and bundles inputs, outputs, and code. Applicability: Agenteer should not only list source data files; it should bind each inspection or scout output to inputs, code/runtime, and generated artifacts. Source: https://arxiv.org/abs/2312.07852

## Design Consequence

The next implementation should enrich `data-access.json` with summary provenance while keeping `table-summary` low-level. The shape should be minimal but PROV-like:

- entity: source file path, size, mtime, SHA-256, format
- activity: table summary generation command/runtime
- agent/software: adapter kind, executable, version, packages
- generated evidence: row/column summary and warnings
