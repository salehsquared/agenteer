# Tick 178 - add-primitive - modeling decision plan

## Axis

Add primitive / methods / architecture.

## Hypothesis

If Agenteer can rank statistical methods, ML adapters, and workflow policies in one modeling plan after a protocol or AnalysisSpec exists, then the research pipeline will stop treating model selection as an implicit human-only step and will choose safer execution paths for survey, predictive, causal, survival, and high-missingness questions.

## Deliverable

Added a modeling decision layer:

- `packages/cli/src/research-machine/modeling.ts`
- `agenteer research modeling-plan`
- public exports for `buildModelingDecisionPlan`
- docs in `docs/research-ml.md`
- tests in `packages/cli/tests/research-ml.test.ts`

The plan combines:

- statistical methods from the existing ontology
- sklearn ML adapters
- workflow policies for complex surveys, missing data, causal stop-for-review, and survival required fields

Saved a CLI smoke artifact at `.loop-memory/modeling/0178-modeling-plan.json`.

## Counter-Design Rejected

I considered putting model choice directly inside `ml-compare`. Rejected because model choice is broader than sklearn prediction: explanatory, survey-weighted, causal, survival, high-missingness, and reporting-policy decisions must be visible before execution.

## Promotion Decision

Promote. This is now the front door for deciding what family of modeling to run before `method-select`, `ml-run`, `ml-compare`, or `paper-run`.

## Remaining Doubt

The plan is deterministic and heuristic. It needs more real-data feedback loops and should eventually consume table summaries, AnalysisSpec V2 directly, and backend availability.
