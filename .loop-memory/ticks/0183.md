# Tick 183 - remove/merge - modeling plan owns method-selection evidence

## Axis

Remove-or-merge / methods / architecture.

## Hypothesis

If `modeling-plan` carries the underlying method-selection identity and hash, the research pipeline needs one fewer parallel decision artifact before execution.

## Deliverable

Merged the method ontology decision into the modeling decision artifact:

- added `methodSelectionEvidence` to `ModelingDecisionPlan`
- included method-selection id, hash, primary method id, recommended backend/archetype, stop-for-review flag, issue codes, and a `method-apply` command hint
- replaced the local ad hoc modeling hash helper with the shared `stableHash`
- rendered method-selection evidence in human output
- documented the unified decision artifact in `docs/research-ml.md`

Saved CLI smoke evidence at `.loop-memory/modeling/0183-merged-modeling-plan.json`.

## Counter-Design Rejected

I rejected keeping `method-select` and `modeling-plan` as two unrelated decision surfaces. The planner should expose the method-selection provenance it already uses internally.

## Promotion Decision

Promote. This reduces artifact drift and gives later AnalysisSpec/model execution steps a stable method-selection bridge.
