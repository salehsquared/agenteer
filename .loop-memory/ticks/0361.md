# Tick 361: unified inspection literature evidence

Axis: faster-simpler
Contribution: UX + reproducibility

## Hypothesis
The packet reviewer should not need to inspect multiple JSON files to learn whether literature evidence was present, weak, warning-level, or failed.

## Deliverable
Extended `research run-inspect` with a first-class literature section: search path, QA path, context path, status, source counts, cited source counts, blocker/warning counts, and next action.

## Verification
`npm run build --workspace @agenteer/cli` passed.
`npx vitest run packages/cli/tests/research-literature.test.ts packages/cli/tests/research-trust.test.ts` passed.

## Counter-Design Considered
Rejected burying literature status inside generic artifact lists because readiness decisions need explicit evidence categories.

## Next Tick
Make literature warnings/failures affect readiness.
