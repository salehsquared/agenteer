# Tick 0198 - Capability-Rave / UX-QA

## Hypothesis

If stats execution declares a typed result posture, lifecycle and future planner gates can distinguish exploratory runs, bound method-governed runs, survey-required blockers, and invalid method bindings without parsing Markdown.

## Scope

- Add machine-readable posture to `research stats-run` results.
- Include posture in stats report and stats QA.
- Surface posture and interpretation boundary in `research paper-lifecycle`.
- Keep the change narrow; do not add new method families in this tick.

## Intervention

Added `StatsResultPosture` with statuses:

- `exploratory_standard_table`
- `bound_standard_table`
- `exploratory_survey_approximation`
- `blocked_survey_required`
- `invalid_binding`
- `failed`

Each posture records label, interpretation boundary, supported uses, unsupported uses, and next action. The runner derives posture from binding status, survey policy, execution status, and blocker issues. `stats-report.md`, `stats-qa.json`, and `paper-lifecycle` now expose it.

## Decision
