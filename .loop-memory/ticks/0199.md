# Tick 0199 - Faster/Simpler / ML-UX

## Hypothesis

If ML runs declare the same kind of typed interpretation posture as stats runs, users and future lifecycle gates can understand what a model output can support without a separate command or manual artifact inspection.

## Scope

- Add typed posture to `research ml-run` outputs.
- Render posture in the existing ML CLI output.
- Cover supervised prediction, unsupervised exploration, optional dependency gaps, and failed execution.
- Avoid adding a new lifecycle command.

## Intervention

Added `MlResultPosture` and runner derivation logic:

- `locally_validated_prediction` for supervised runs with held-out or CV evidence and a primary metric.
- `exploratory_unsupervised` for clustering and dimensionality reduction.
- `optional_dependency_missing` for optional adapters such as XGBoost when unavailable.
- `failed` for other execution failures.

The posture records label, interpretation boundary, supported uses, unsupported uses, and next action. Text rendering now shows `posture` and `boundary`.

## Decision

Keep ML posture as a core artifact field. This makes ML outputs less ambiguous and creates a shared predicate for later lifecycle/readiness work across stats and ML.

## Counter-Design Considered

Rejected adding a new `ml-lifecycle` command. The simpler and more reusable move was to make the existing `ml-run` artifact self-describing enough for current and future lifecycle surfaces.
