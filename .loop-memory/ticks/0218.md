# Tick 0218 - More Robust / Multi-Route Benchmark Gate

## Hypothesis

If benchmark promotion scripts can require multi-route coverage, a single strong ML or stats route cannot accidentally masquerade as broad research-pipeline maturity.

## Scope

Add a strict opt-in gate to the existing benchmark command.

## Intervention

- Added `--require-multi-route` to `research analysis-benchmark`.
- Made `route-coverage` a failing check only when that strict gate is requested.
- Kept default single-route behavior as pass-with-warning to preserve focused development workflows.
- Updated tests and docs.
- Regenerated the live two-route benchmark and saved a strict single-route failure artifact.

## Evidence

Verification passed:

- `npm run build`
- `npm test -- packages/cli/tests/research-ml.test.ts -t "summarizes route coverage"`

CLI smoke:

- ML-only strict benchmark exits `1`, status `fail`, coverage `single_route`.
- Stats+ML strict benchmark exits `0`, status `pass`, coverage `multi_route_ready`.

## Decision

Promote the strict opt-in gate.

## Counter-Design Considered

Rejected making all benchmarks require multiple routes by default. Single-route checks remain useful during focused development and regression testing.

Updated `MEMORY.md`, `improvements.md`, `open-questions.md`, and `rejected.md`.
