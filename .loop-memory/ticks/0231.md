# Tick 0231 - Tail Sample / Diagnostic Paper Wrapper

## Hypothesis

The smallest useful diagnostic paper path is to let `analysis-run --method diagnostic-accuracy` write a concise local-review paper from its own stats-run artifacts.

## Scope

Code, tests, docs, golden route refresh, and benchmark rerun.

## Intervention

- Added diagnostic `paper.md` and `paper-qa.json` generation to `research analysis-run` when the method is `diagnostic-accuracy`.
- Paper output includes local review safety header, reference standard, index test, thresholds, confusion matrix values, Wilson intervals, PPV/NPV prevalence caveat, and screening-overclaim boundary.
- Added targeted test coverage for generated diagnostic paper and QA.
- Refreshed `.loop-memory/golden/0229-diagnostic-threshold-route` so it now includes a paper packet.
- Updated `docs/research-ml.md`.

## Evidence

- `npm run build` passed.
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"` passed.
- Live threshold diagnostic route wrote `analysis-run/paper.md` and `analysis-run/paper-qa.json`.
- Paper QA status is `pass`.
- Strict four-route benchmark remains pass.

## Verification

Build, targeted test, live paper-generation CLI run, paper QA inspection, and strict benchmark all passed.

## Decision

Keep this as a narrow diagnostic wrapper inside `analysis-run`, not a broad new paper subsystem.

## Counter-Design Considered

Rejected adding a new `research diagnostic-paper` command because the existing bounded `analysis-run` route already owns this artifact family.
