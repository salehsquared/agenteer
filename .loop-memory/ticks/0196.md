# Tick 196 - web-search - stats-run packet-grade artifacts

## Axis

Web-search / maturity runner + QA.

## Scope

Respond to Tick 195 by making `stats-run` produce packet-grade review artifacts instead of only computational outputs.

## Hypothesis

If `stats-run` emits a local-review report and QA artifact with p-value/effect-size cautions, uncertainty framing, binding status, and standard-table limitations, then standard-table statistical execution becomes closer to a complete research packet path.

## Intervention

Added packet-grade artifacts to every `stats-run` result:

- `stats-report.md`
- `stats-qa.json`
- artifact hashes for both
- renderer output paths for report and QA
- modeling-plan route artifacts now include the report and QA files
- docs updated

The report includes a local review safety header and ASA-style interpretation cautions. The QA artifact checks execution status, estimate-table presence, uncertainty/p-value context, binding status, and standard-table/survey boundary.

## Evidence

Web sources used:

- ASA p-value statement: p-values require context, full reporting, and do not measure effect size or practical importance.
- ASA Task Force statement: replicability risks include poor design, model-choice gaps, inadequate analytic procedure descriptions, and selective reporting.
- TRIPOD+AI supplement: prediction reports should describe performance measures, calibration, model details, uncertainty, limitations, and avoid overinterpretation.

## Decision

Promote. `stats-run` is still not a full paper generator, but it now produces reviewable packet-grade artifacts without a new command.

## Counter-Design Considered

I rejected a separate `stats-report` command. Generating report/QA at execution time keeps hashes and lifecycle evidence tied to the exact runner result.
