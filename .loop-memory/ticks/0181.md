# Tick 181 - faster/simpler - evidence-aware modeling plan

## Axis

Faster/simpler / methods / architecture.

## Hypothesis

If `modeling-plan` can read table evidence directly, users and agents will need fewer manual flags and will get safer model rankings before execution.

## Deliverable

Responded to the Tick 179-180 critiques by making `research modeling-plan` evidence-aware:

- added `--table <rows.csv|json|parquet>` and `--table-summary <summary.json>`
- added `--target <column>`
- derived row count, feature count, target class count, maximum missingness, high-missingness, small-sample, and high-dimensional signals
- split `blockingPolicies` from executable candidates
- downgraded high-capacity ML for small or high-missingness tables
- required calibration/Brier/threshold-policy metrics for binary clinical prediction candidates
- added unsupported-domain policy candidates for text, image, spatial, and network modeling
- updated `docs/research-ml.md`

Saved CLI smoke evidence at `.loop-memory/modeling/0181-evidence-aware-modeling-plan.json`.

## Counter-Design Rejected

I rejected making users manually pass `--small-sample`, `--high-missingness`, and `--feature-count` once a table file is available. The command should derive those from evidence.

## Promotion Decision

Promote. `modeling-plan` is now acceptable as decision support before model execution, though it still needs AnalysisSpec V2 and backend-status ingestion.

## Remaining Doubt

The evidence is table-level, not merged-cohort-level. For actual NHANES work, the strongest signal still comes after cohort feasibility and variable mapping.
