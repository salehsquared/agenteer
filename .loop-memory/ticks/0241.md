# Tick 0241 - faster-or-simpler - readability gates

## Axis

faster-or-simpler

## Hypothesis

A small deterministic readability layer will improve generated papers more reliably than ad hoc prose edits.

## Scope

Improve paper-run generation and paper QA for reader-facing readability. Do not change domain repos or the statistical result.

## Intervention

Added a small NHANES variable-label map in the paper-run generator and used it in the abstract, methods, results, and discussion. Added paper QA checks for:

- main-finding sentence
- raw variable-code density
- awkward generator phrases

Regenerated the latest actual NHANES R-survey paper and paper index.

## Deliverable

The latest paper now says “body mass index” and “fasting plasma glucose” instead of leading with `BMXBMI` and `LBXGLU`, includes a `Main finding:` sentence, keeps raw codes to a small auditable set, and still passes paper QA, lifecycle, and task validation.

## Evidence

`qa-cli.json` for `0179-bmi-fasting-glucose-r-survey` reports:

- `reader-facing-language: pass`
- `reader-code-density: pass`
- `reader-awkward-generator-phrases: pass`
- `reader-main-finding: pass`
- `reader-safety-summary: pass`

## Verification

- `npm run build`
- `npm test -- packages/cli/tests/research.test.ts -t "paper"`

- `agenteer research paper-index --papers-dir .loop-memory/actual-nhanes/papers --out .loop-memory/actual-nhanes/PAPER_INDEX.md --json`

## Decision

Use human labels as the default paper language while retaining a small number of parenthetical codes for auditability.

## Counter-Design Considered

I rejected hiding all raw variable codes. Readers need labels, but reviewers still benefit from seeing the underlying variable code at least once.
