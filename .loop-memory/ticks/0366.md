# Tick 366: analysis-run literature context persistence

Axis: question-the-question
Contribution: architecture + reproducibility

## Hypothesis
If literature shapes route choice, it must be persisted in the packet, not only computed transiently during planning.

## Deliverable
`analysis-run --literature` now writes local `literature-context.json` and `literature-context.md` beside the copied search and generated literature QA artifacts.

## Verification
`packages/cli/tests/research-literature.test.ts` now checks `generatedFiles.literatureContext`, `generatedFiles.literatureContextReport`, and manifest inclusion.

## Counter-Design Considered
Rejected keeping context only in `modeling-plan.json`, because context is independently useful for reviewers and later reruns.

## Next Tick
Feed literature context into pre-run and post-run modeling plans.
