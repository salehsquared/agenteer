## Axis

add-primitive / UX, methods, architecture

## Hypothesis

The first exploration smoke run showed that a globally strongest unrelated pair can outrank the user-declared target. If `research explore --target` separates target-centered evidence from the background correlation map, it will produce better candidate research questions while still preserving whole-dataset understanding.

## Scope

Primary repo only. No MedBrevia writes. Tighten the exploration contract, docs, test expectations, and golden smoke output.

## Intervention

Added target-aware exploration fields:

- `targetAssociations`: ranked associations involving the declared target.
- `backgroundAssociations`: ranked associations that do not involve the declared target.

The report now renders `Target-Centered Associations` before `Background Correlation Map`, and candidate questions begin with target-focused associations when available. QA now includes `target-association-scan`.

## Deliverable

- Updated exploration JSON contract and renderer in `packages/cli/src/commands/research.ts`.
- Updated exploration test expectations in `packages/cli/tests/research-ml.test.ts`.
- Updated docs in `docs/research-ml.md`.
- Regenerated `.loop-memory/golden/0243-exploration-mode`.

## Evidence

The regenerated report foregrounds:

- `bmi vs hba1c`
- `age vs hba1c`
- `hba1c vs hdl`
- `hba1c vs income`

The unrelated `sex vs smoker` signal is retained under the background map rather than becoming the first candidate question.
