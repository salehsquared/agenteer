# Tick 0223 - Faster/Simpler / Diagnostic Accuracy Route

## Hypothesis

Diagnostic accuracy should be a first-class executable standard-table method instead of a research-design idea that requires manual Python.

## Scope

Code, tests, docs, and a live golden route.

## Intervention

- Added `diagnostic-accuracy` to the stats-run method schema.
- Mapped `diagnostic-accuracy-basic` to `diagnostic-accuracy`.
- Implemented binary reference/test conversion, confusion matrix, sensitivity, specificity, PPV, NPV, accuracy, prevalence, LR+, LR-, and sparse-cell warnings in the local stats runner.
- Updated `docs/research-ml.md`.
- Added targeted Vitest coverage.
- Created `.loop-memory/golden/0223-diagnostic-accuracy-route`.

## Evidence

- `npm run build` passed.
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"` passed.
- `research analysis-run --method diagnostic-accuracy --require-bound` produced a `local_review_ready` manifest.
- `research analysis-benchmark --require-ready --require-multi-route` passed across:
  - `.loop-memory/golden/0216-bound-stats-route`
  - `.loop-memory/golden/0223-diagnostic-accuracy-route`
  - `.loop-memory/golden/0212-ml-comparison-route`

## Counter-Design Considered

Rejected implementing diagnostic accuracy only inside generated paper code because it would bypass method-selection binding, stats-run QA, analysis manifests, and multi-route benchmark evidence.

## Result

Agenteer can now run and benchmark diagnostic accuracy as a reusable standard-table route.

## Decision

Keep diagnostic accuracy as a standard-table stats-run primitive and use it as a new benchmark route for non-regression clinical methods.

## Verification

Validated through build, targeted tests, live CLI execution, manifest readiness, and strict multi-route benchmark.

## Memory Updates

Updated `MEMORY.md`, `candidates.md`, `improvements.md`, `open-questions.md`, and `rejected.md`.
