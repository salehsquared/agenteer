# Tick 0228 - Cross-Domain / Diagnostic Wilson Intervals

## Hypothesis

Diagnostic metrics should include tolerance-like uncertainty intervals, not only point estimates.

## Scope

Code, tests, refreshed golden artifacts, and benchmark rerun.

## Intervention

- Added Wilson binomial intervals for sensitivity, specificity, PPV, and NPV in `diagnostic-accuracy`.
- Rendered diagnostic intervals directly in `stats-report.md`.
- Upgraded `diagnostic-precision-caveat` from a permanent warning to a pass when intervals are present.
- Extended targeted diagnostic regression coverage.
- Refreshed `.loop-memory/golden/0223-diagnostic-accuracy-route`.

## Evidence

- `npm run build` passed.
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"` passed.
- Live diagnostic run now includes sensitivity interval 0.7261 to 0.8887 for sensitivity 0.8214.
- Diagnostic precision QA passes.
- Strict three-route benchmark remains pass.

## Verification

Build, targeted test, live diagnostic route rerun, interval inspection, QA inspection, and strict benchmark all passed.

## Decision

Wilson intervals are the default local diagnostic interval method for now because they are deterministic, cheap, and appropriate for binomial proportions in a standard-table route.

## Counter-Design Considered

Rejected bootstrap intervals for this tick because they add randomness and rerun-stability burden before exact deterministic intervals exist.
