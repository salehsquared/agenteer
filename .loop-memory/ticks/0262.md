# Tick 0262 - Add Primitive - Pre-Spec Exploration Handoff

## Scope

Label: `methods`, `reproducibility`, `architecture`.

Close the exploration-mode pass by bridging handoff artifacts toward AnalysisSpec authoring without pretending exploratory output is executable.

## Hypothesis

If `explore-promote` writes a pre-spec candidate, the exploration-to-study path becomes more concrete while preserving the methods-review boundary.

## Intervention

- Added `analysisSpecCandidate` to `ResearchExplorationHandoff`.
- The candidate records:
  - status
  - route intent
  - research question
  - estimand boundary
  - source population/table
  - outcome/exposure/covariates
  - excluded variables pending review
  - design requirements
  - suggested model family
  - required pre-execution checks
  - provenance linking source exploration hash, question id, taxonomy version, and route intent
- Updated docs, tests, and text rendering.
- Regenerated the actual NHANES handoff and modeling-plan artifacts.

## Evidence

Actual NHANES handoff now includes:

- status: `needs_methods_review`
- route: `explanatory_association`
- outcome: `LBXGH`
- exposure: `RIDAGEYR`
- excluded-until-reviewed variables: `elevated_hba1c`, NHANES design fields, and weights
- required pre-execution check: write or approve an AnalysisSpec before execution
- provenance: source exploration path/hash, question id, taxonomy version, route intent

## Verification

- `./node_modules/.bin/tsc --build` passed.
- Actual-data `explore-promote` smoke passed.
- Actual-data `modeling-plan --exploration-handoff --survey` smoke passed.
- Targeted Vitest remains blocked before test execution by the local Rollup native optional dependency/code-signature issue.

## Decision

Promote. The handoff is now an inspectable pre-spec bridge.

## Counter-Design Considered

Rejected writing a full executable AnalysisSpec directly from exploratory output. The correct bridge is a candidate with explicit methods-review status and required pre-execution checks.
