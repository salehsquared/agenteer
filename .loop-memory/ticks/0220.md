# Tick 0220 - Challenge / Paper Benchmark Separation

## Hypothesis

The stats/ML benchmark can now pass while the paper-generation path still degrades, because paper-run lifecycle evidence is not part of the analysis benchmark suite.

## Scope

Challenge and memory hygiene. No code changes.

## Intervention

Reviewed the active golden tasks, recent benchmark work, and the paper-run lifecycle thread.

## Critique

The current system now has two strong but separate proof families:

- `analysis-benchmark`: standard-table stats and ML comparison readiness.
- `paper-run` lifecycle: NHANES/public-health paper generation with survey-aware runners, QA, task envelopes, and rerun stability.

That split is defensible, but it creates a fake-progress risk. A future agent could pass the analysis benchmark and claim the research platform is healthier while the actual paper path is untouched. Conversely, a generated paper could pass lifecycle while the stats/ML route benchmark fails.

Specific gaps:

- No single reviewer-facing "research machine health" summary joins analysis benchmarks and paper lifecycle.
- The current active benchmark excludes the survey-paper path, which is the hardest and most medically relevant route.
- Paper artifacts are excellent for local review but expensive to regenerate; the loop needs cheaper paper-health smoke checks.
- Memory now has enough history that old entries can obscure active blockers unless the open thread stays precise.

## Evidence

Current active route evidence:

- Bound stats route: `.loop-memory/golden/0216-bound-stats-route`
- ML comparison route: `.loop-memory/golden/0212-ml-comparison-route`
- Current paper route family: `.loop-memory/actual-nhanes/papers/`

## Decision

Do not merge paper-run into `analysis-benchmark` yet. The next implementation should add a thin research-machine health summary that composes existing analysis benchmark and paper lifecycle artifacts without inventing a new readiness ontology.

## Counter-Design Considered

Rejected forcing paper-run directories into `analysis-benchmark`. Paper packets have lifecycle/task/rerun semantics that are richer than `analysis-manifest` and should not be flattened prematurely.
