# Tick 186 - question-the-question - make stats-run governed, not convenient

## Axis

Question-the-question / methods / safety.

## Question

Should `stats-run` be a broad convenience command, or should it behave like a governed execution primitive?

## Answer

It should be governed. Convenience is useful for exploration, but the research pipeline's differentiator is refusing misleading medical/public-health inference before it becomes a paper artifact.

## Deliverable

Responded to the Tick 185 challenge by strengthening `stats-run`:

- added typed `issues` to `StatsRunResult`
- added default refusal for `--survey` unless `--allow-survey-approximation` is explicit
- added typed issues for sparse expected cells, low complete-case N, survey approximation, regression non-convergence, possible logistic separation/extreme log-odds, and Poisson overdispersion
- updated human rendering, docs, CLI help, and tests

Saved CLI refusal smoke evidence under `.loop-memory/modeling/0186-stats-safety/`.

## Counter-Design Rejected

I rejected keeping `--survey` as an ignored hint. If the user declares survey design, a standard non-survey runner must stop or clearly mark approximation.

## Promotion Decision

Promote. `stats-run` remains usable for standard tables, but now has a safety boundary that matches the research pipeline's methods posture.
