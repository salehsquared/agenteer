# Tick 0238 - first-principles - paper language index

## Axis

first-principles

## Hypothesis

If papers are durable artifacts, the system needs a durable way to tell current reader-facing outputs from legacy outputs. A separate scan is too easy to forget; the distinction belongs in the paper index.

## Scope

Extend the existing `research paper-index` surface. Do not add a new command and do not rewrite legacy historical papers.

## Intervention

Added reader-facing language status to paper index entries. Each indexed paper now reports whether `paper.md` passes the internal-term audit, is missing, or is `legacy_or_fail` with the matched terms.

## Deliverable

- `ResearchPaperIndex` now includes `readerFacingLanguageStatus` and `readerFacingLanguageHits`.
- `renderResearchPaperIndex` now includes a `Reader Language` column.
- The paper-index test now covers a clean paper and a legacy paper containing internal terms.
- Generated `.loop-memory/actual-nhanes/PAPER_INDEX.md` and `.loop-memory/actual-nhanes/paper-index.json`.

## Evidence

The generated actual-NHANES paper index shows `0179-bmi-fasting-glucose-r-survey` as `pass` and identifies 11 legacy/pre-contract papers with the exact terms that need interpretation caution.

## Verification

- `npm run build`
- `npm test -- packages/cli/tests/research.test.ts -t "paper"`
- `agenteer research paper-index --papers-dir .loop-memory/actual-nhanes/papers --out .loop-memory/actual-nhanes/PAPER_INDEX.md --json`
- `jq` count over `paper-index.json`: 1 reader-facing pass, 11 legacy/fail

## Decision

Fold paper-language audit into the discovery/index view instead of adding a parallel command.

## Counter-Design Considered

I rejected rewriting all historical `paper.md` files. They are useful chronology, but they should be labeled clearly as pre-contract artifacts.

- Updated `open-questions.md` and `rejected.md`.
