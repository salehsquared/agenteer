# Tick 0232 - Add Primitive / Diagnostic Paper Manifest Visibility

## Hypothesis

Diagnostic paper artifacts should be visible to analysis manifests when present, otherwise future agents will miss them during inspection.

## Scope

Code, tests, golden route refresh, and benchmark rerun.

## Intervention

- Added optional `diagnostic-paper` and `diagnostic-paper-qa` artifacts to stats analysis manifests when root-level paper files exist.
- Rebuilt the analysis manifest after diagnostic paper generation inside `analysis-run`.
- Added targeted test coverage for manifest visibility.
- Refreshed the threshold diagnostic golden route.

## Evidence

- `npm run build` passed.
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"` passed.
- Live diagnostic manifest now lists existing hashed `diagnostic-paper` and `diagnostic-paper-qa` artifacts.
- Strict four-route benchmark remains pass.

## Verification

Build, targeted test, live route rerun, manifest inspection, and strict benchmark all passed.

## Decision

Keep diagnostic paper artifacts optional in `analysis-manifest`; they improve inspection but should not block ordinary stats-run readiness.

## Counter-Design Considered

Rejected making diagnostic paper artifacts required for all stats routes because that would break plain standard-table workflows and confuse local-review readiness.
