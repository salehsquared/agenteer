# Tick 0229 - Faster/Simpler / Diagnostic Threshold Derivation

## Hypothesis

Explicit threshold flags are the simplest safe way to let diagnostic accuracy operate on continuous biomarker or screening columns.

## Scope

Code, CLI wiring, docs, tests, new golden route, and benchmark rerun.

## Intervention

- Added `outcomeThreshold` and `exposureThreshold` to `StatsRunRequest`.
- Added CLI flags `--outcome-threshold` and `--exposure-threshold` for `stats-run` and `analysis-run`.
- Implemented deterministic `>= threshold` binary derivation in the Python stats bridge.
- Added threshold metadata to diagnostics.
- Updated docs and targeted diagnostic regression coverage.
- Created `.loop-memory/golden/0229-diagnostic-threshold-route`.

## Evidence

- `npm run build` passed.
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"` passed.
- Threshold-derived diagnostic route produced `local_review_ready`.
- Live route recorded reference threshold 6.5 and test threshold 100.
- Strict four-route benchmark passed with 4/4 local-review-ready manifests.

## Verification

Build, targeted test, threshold route CLI run, and strict benchmark all passed.

## Decision

Use explicit threshold flags before any automatic threshold search. This keeps diagnostic derivation auditable and reproducible.

## Counter-Design Considered

Rejected automatic optimal cutoff search because it risks overfitting and would require validation/split policy before local-review readiness.
