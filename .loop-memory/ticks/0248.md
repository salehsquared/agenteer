## Axis

more-robust / QA, architecture, UX

## Hypothesis

Exploration is safer if promotion is an explicit command that enforces clearance. If `research explore-promote` refuses held or blocked questions unless the operator supplies methods-review evidence, the pipeline becomes harder to misuse while still supporting creative discovery.

## Scope

Primary repo only. Add one robust boundary command, docs, tests, and golden smoke artifacts.

## Intervention

Added `research explore-promote --exploration <exploration.json> --question <id> [--methods-review-note <text>] [--out <handoff.json>] [--json]`.

The command:

- reads raw `exploration.json` or an `{"exploration": ...}` envelope;
- selects one candidate question;
- refuses `stop` clearance or blocked questions;
- requires `--methods-review-note` for `hold_for_methods_review` or `needs_methods_review`;
- writes a handoff artifact with source hash, blockers, modeling-plan seed, and recommended command.
