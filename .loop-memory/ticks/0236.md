# Tick 0236 - more-robust - reader-facing paper contract

## Axis

more-robust

## Hypothesis

Generated papers will be easier to read and less misleading if `paper.md` is treated as a scientific-reader artifact and internal platform vocabulary is blocked by deterministic QA.

## Scope

Only the paper-generation and paper-QA boundary changed. Internal manifests, runner records, lifecycle files, and evidence receipts still keep platform terminology for auditability.

## Intervention

Rewrote the diagnostic `analysis-run` paper generator and the NHANES `paper-run` template, then added a paper-QA check for forbidden reader-facing framework language.

## Deliverable

Implemented a reader-facing paper language contract in code:

- Rewrote diagnostic `analysis-run` paper output so `paper.md` presents the question, methods, results, interpretation, limitations, and reproducibility note without platform jargon.
- Rewrote the NHANES `paper-run` generated paper template to describe methods directly instead of talking about Agenteer or internal execution concepts.
- Added deterministic paper QA that fails reader-facing papers containing internal terms such as `Agenteer`, `AnalysisSpec`, `result posture`, `local_review_ready`, `artifact posture`, `runner record`, `task envelope`, `evidence receipt`, `interop`, `spec-governed`, or `paper-run`.
- Updated paper QA tests and diagnostic route tests to enforce the new language boundary.
- Regenerated the current diagnostic threshold golden route and repeat route; both current diagnostic `paper.md` files now pass the forbidden-term scan.

## Evidence

The regenerated diagnostic paper now begins with a plain-language summary and methods/results/limitations sections. Its `paper-qa.json` reports `reader-facing-language: pass`.

## Verification

- `npm run build`
- `npm test -- packages/cli/tests/research-ml.test.ts -t "diagnostic accuracy"`
- `npm test -- packages/cli/tests/research.test.ts -t "paper"`
- `agenteer research analysis-run ... --method diagnostic-accuracy ...` for baseline and repeat diagnostic golden routes
- `find .loop-memory/golden/0229-diagnostic-threshold-route -path '*/paper.md' ... rg forbidden terms` returned no matches

## Decision

Keep the audience boundary structural: `paper.md` should avoid internal terms, while provenance files retain them.

## Counter-Design Considered

I rejected stripping internal terminology from all JSON/provenance artifacts. The right boundary is `paper.md`: readers get scientific prose, while manifests, lifecycle records, and runner records keep precise platform terms for auditability.
