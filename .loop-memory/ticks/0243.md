## Axis

capability-rave / architecture, methods, UX

## Hypothesis

Agenteer needs a real dataset exploration mode before it can choose better research questions. If the CLI can summarize a table, classify variable roles, rank plausible unadjusted associations, and write candidate questions with explicit exploratory limits, the research pipeline can generate better downstream AnalysisSpec/modeling-plan inputs without hiding that the findings are hypothesis-generating.

## Scope

Primary repo only. No MedBrevia writes. Add one bounded command and its documentation, tests, and golden smoke artifact.

## Intervention

Implemented `agenteer research explore --data <csv|json|parquet> [--target <column>] [--out-dir <dir>] [--max-pairs <n>] [--json]`.

The command now:

- runs the existing table-summary path for provenance and basic shape;
- reads CSV/JSON directly and Parquet through the existing explicit Python/pandas bridge;
- maps variable roles as target, candidate outcome/exposure, identifier/index, metadata/weight, low-information, or feature;
- ranks numeric-numeric, numeric-categorical, and categorical-categorical associations using Pearson absolute value, eta-squared, and Cramer's V;
- generates candidate research questions with suggested methods, rationale, priority, and required next checks;
- writes `exploration.json`, `exploration-report.md`, and `candidate-questions.json` with artifact hashes;
- labels output as `exploratory_hypothesis_generation` and warns that associations are unadjusted and not causal or publication-ready.

## Decision

Keep experimental but useful. Promote the command as a bounded hypothesis-generation surface, not a research-answer surface.

## Counter-Design Considered

Rejected automatic paper/AnalysisSpec generation directly from exploration. It would make unadjusted correlations look more confirmatory than they are.
