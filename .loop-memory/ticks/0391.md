# Tick 0391: core inference validation corpus

Axis: first-principles
Divergence: first-principles
Contribution: truth + methods + QA

## Hypothesis

If the expanded stats runner is real, a clean clinical-style table should support core inference routes from CLI and produce inspectable artifacts with denominators, QA, and figures where appropriate.

## Scope

Create the validation corpus and run the first method family: core inference and association.

## Intervention

Created `.loop-memory/stats-method-validation-20260509/validation-data.csv` with 240 synthetic clinical-style records and ran:

- `welch-t-test`
- `paired-t-test`
- `anova`
- `chi-square`
- `partial-correlation`

Generated a manuscript and run inspection for the ANOVA route as the first reader-facing proof.

## Evidence

- Validation table: `.loop-memory/stats-method-validation-20260509/validation-data.csv`.
- Core runs: `.loop-memory/stats-method-validation-20260509/runs/0391-*`.
- All five core routes returned `status=succeeded`.
- Complete-case N was 240 for all five routes.
- QA status was `warning` for route-level stats QA, not failed.
- Figure artifacts were produced for Welch, ANOVA, chi-square, and partial correlation; paired t-test correctly had no natural figure.
- ANOVA manuscript QA passed and run inspection had zero blockers.

## Verification

Ran each route through `node packages/cli/dist/bin/agenteer.js research stats-run`, then ran `research manuscript` and `research run-inspect` on the ANOVA packet.

## Decision

Promote the core-inference subset from "registered" to "validated against a local corpus", with the caveat that generic stats QA still reports warnings until method-specific interpretability gates become richer.

## Counter-Design Considered

Rejected using only the Vitest synthetic fixture because it does not persist a reviewer-facing validation corpus or manuscript output.

## Memory Updates

Recorded the validation corpus and first executable family results.
