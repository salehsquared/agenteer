## Findings

- BagIt separates payload files from tag/metadata files and defines valid packages by manifest checksum verification. Its manifest entries use paths relative to the package base, not absolute local filesystem paths. Applicability: Agenteer export should treat shareable packet artifacts as payload, generate relative-path checksum manifests, and scan all exported files for local absolute paths. Source: https://datatracker.ietf.org/doc/html/rfc8493
- Reproducibility guidance from LTER/SSECR recommends relative, OS-flexible project paths, while putting user-specific absolute paths into ignored local configuration when unavoidable. Applicability: Agenteer should keep `data-access.json` as a local rerun artifact and export a redacted, source-ref-based view instead. Source: https://lter.github.io/ssecr-2024/mod_reproducibility.html
- RO-Crate is framed as a lightweight structured archive for research artifacts plus machine-readable provenance, identifiers, relations, and annotations. Applicability: Agenteer should keep `data-access-redacted.json` derivation metadata and eventually describe it in RO-Crate/export metadata. Source: https://arxiv.org/abs/2108.06503
- Workflow Run RO-Crate focuses on workflow-run provenance for traceability, reproducibility, and quality assessment. Applicability: Agenteer export should record not only artifacts but which command/activity generated or transformed them. Source: https://arxiv.org/abs/2312.07852

## Creative Implications

- Bag boundary: split packet artifacts into `shareable`, `local-only`, and `derived-redacted` classes.
- Path escrow: preserve local absolute paths only in a non-exported or explicitly quarantined local metadata file.
- Export receipt: export should produce a machine-readable scan result proving no shareable artifact contains `/Users/...`.
- Derived artifact chain: every scrubbed artifact should name its source hash without naming its source path.
