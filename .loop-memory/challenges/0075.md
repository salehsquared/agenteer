# Tick 0075 Challenge: Profile Naming Does Not Solve Statistical Adequacy

Persona: Skeptical statistician

## Critique

Naming the readiness profile is good, but it still does not prove that the statistical analysis is adequate. A packet could be `observational-survey-v1`, have all readiness components pass, and still mishandle design weights, model specification, nonlinear terms, multiple comparisons, missingness mechanisms, or sparse subgroups.

The risk is subtle: profile naming can make the review look more formal than it is. The command should keep reminding users that the profile indicates the review lens, not a statistical seal.

## Actionable Implications

- Keep `readinessProfile.caveat` visible in human output.
- Avoid profile ids that sound like certification.
- Future profile work should include explicit unmet statistical assumptions, not only references.

## Evidence That Would Change This Critique

I would soften the critique if the human readiness output showed the profile caveat and if future statistical adequacy lived in `methods-validation`, not in the readiness profile name.
