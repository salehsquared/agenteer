# Tick 190 Challenge - Reliability Engineer

## Critique

The last set of ticks made standard-table statistics much more real, but the system has not yet proven that this path produces a paper-grade packet. The tests prove local command behavior: methods run, survey misuse refuses, binding catches mismatches, and mapping does not drift. They do not yet prove end-to-end research reliability.

The main reliability risk is that `stats-run` is a new runner family with its own result schema, issue schema, artifacts, docs, and tests. That is acceptable only if lifecycle, packet manifests, and paper QA can consume it. Otherwise Agenteer has created a second execution island next to `paper-run` and `ml-run`.

The second risk is operational: Python bridge code is embedded in a TypeScript string. This follows the existing ML runner pattern, but the stats bridge is already large enough that debugging, linting, and test isolation will get worse as methods expand. If the bridge grows again, extract it to a template/module with explicit fixtures.

The third risk is methods reliability: typed issues exist, but severity policy is still immature. Possible separation is a warning even when it may invalidate interpretation; low complete-case N is a warning regardless of model family; overdispersion warns but does not select an alternative. That is better than silence, not enough for automatic paper generation.

## Actionable Implications

- Run a real standard-table golden packet through `modeling-plan -> method-select -> stats-run -> manifest/paper QA`.
- Teach lifecycle/readiness to consume `StatsRunResult.binding` and `StatsIssue`.
- Split stats tests/docs from ML tests/docs before more methods are added.
- Promote bridge extraction if stats methods expand beyond the current set.
- Add severity policy keyed by method family and intended use: exploratory, local review, paper-ready.

## Evidence That Would Change This Critique

- A real generated paper packet whose primary analysis artifact is `stats-run.json`.
- A lifecycle summary that blocks local review when `StatsIssue` has blocker status and warns on exploratory survey approximation.
- A regression test that edits method-selection to a different method and proves the packet cannot pass readiness.
