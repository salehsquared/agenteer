# Tick 0390 Challenge: Framework Minimalist Review

Persona: Framework minimalist

## Critique

The expanded statistics runner is in danger of becoming a catalog-shaped feature: many method names, many command flags, and many artifacts, but no single reviewer-facing proof that a given study used the right route. The platform should not optimize for saying "we support X" until it can show the selected route, assumptions, denominator, QA, figures, and blockers in one packet.

The most likely fake-progress mode is that a method returns `status=succeeded` while the report is still too thin for a methods reviewer. This is especially likely for routes that are mathematically valid but context-sensitive: survival, causal weighting, missingness, reliability, and prediction.

## Actionable Implications

- The validation corpus should include packet-level manifests and inspections, not only `stats-run.json`.
- The suite should record methods that run but remain "review only" because assumptions are unverified.
- Figure output needs to be checked as real files with captions, not only the existence of `figures.json`.
- The final index should separate **implemented and validated**, **implemented but review-limited**, and **registered but blocked**.

## Evidence That Would Change This Critique

The critique is weakened if the next ticks produce a durable validation corpus with:

- at least one reviewable diagnostic or propensity paper;
- several stats reports/manuscripts covering different method families;
- a table of all executed methods, status, QA status, figure count, and blockers;
- a negative-control run showing backend-missing methods fail clearly;
- targeted tests passing after the corpus is generated.
