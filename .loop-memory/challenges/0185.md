# Tick 185 Challenge - Skeptical Statistician

## Critique

`research stats-run` is valuable, but it is not yet safe as a research-facing execution primitive unless it is bound to a protocol or AnalysisSpec. Right now it will run a method from flags alone. That makes it easy to run a t-test on paired data, ignore survey design, fit a logistic model with quasi/perfect separation, or report a Poisson model despite overdispersion as if the model were adequate.

The runner also mixes "standard table statistics" and "research-ready inference" too closely. It records estimates and diagnostics, but it does not yet enforce method-selection provenance, model family compatibility, minimum complete-case N, sparse-cell policy, multiplicity policy, missingness policy, or survey-design refusal. The docs say it does not replace `r-survey`; the command itself should make that boundary machine-checkable.

The logistic smoke test exposed a real warning: perfect-separation warnings can occur and still produce extreme odds ratios. That should not be hidden as a mere stderr append. Separation, singular design matrices, convergence failure, extreme estimates, and overdispersion should become typed diagnostics that can block paper generation or require methods review.

## Actionable Implications

- Add a stats execution contract that can be created from method-selection evidence or AnalysisSpec V2.
- Add typed warnings/failures for separation, overdispersion, sparse cells, low complete-case N, non-binary outcome/group, non-2x2 Fisher tables, and survey-design misuse.
- Add a `--survey-design` or AnalysisSpec-derived refusal path so standard stats cannot silently analyze complex surveys without an explicit non-survey/exploratory posture.
- Add a model diagnostics artifact schema for regression convergence, design matrix rank, complete-case flow, and influential failure classes.
- Make `modeling-plan` candidates point to `stats-run` only when a method is executable and the required fields are known.

## Evidence That Would Change This Critique

- A CLI smoke run where `method-select -> method-apply -> execution-contract -> stats-run` preserves method id and spec hash.
- A regression test where survey-shaped data is refused by `stats-run` unless explicitly marked exploratory/non-survey.
- A regression test where perfect separation or Poisson overdispersion produces typed review-blocking diagnostics.
- A generated paper packet whose classical stats runner provenance is accepted by lifecycle/readiness without bespoke glue.
