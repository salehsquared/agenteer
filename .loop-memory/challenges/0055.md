# Tick 0055 Challenge: The Research CLI Is Accreting Too Many Names

Persona: Framework minimalist

## Critique

The latest improvements are useful, but the command surface is becoming a memorization burden: `checkpoint`, `next`, `packet-summary`, `packet-verify`, `packet-readiness`, `qa-dashboard`, `stage-artifacts`, `manifest-verify`, `navigation-trace`, and `approval-verify` are all adjacent. A new contributor cannot easily infer which command to run first.

This matters because Agenteer is supposed to be an orchestration substrate. If every new concept becomes a top-level command, the framework teaches users to browse commands rather than follow a workflow. The research pipeline needs fewer entry points with clearer drill-downs.

## Actionable Implications

- Do not add another research command until at least one command is hidden, aliased, documented as low-level, or integrated into `research next`.
- Consider `research status` as a future umbrella over checkpoint, next, packet-verify, packet-readiness, and qa-dashboard.
- For now, improve help/docs ordering or add "primary path" labels rather than expanding behavior.
- Treat `stage-artifacts`, `approval-verify`, `navigation-trace`, and `manifest-verify` as audit/debug commands.

## Evidence That Would Change This Critique

I would soften the critique if the CLI had a primary happy path and a separate audit/debug section, even if the underlying commands remain available.

## Recommended Next Tick

Make the CLI help distinguish primary workflow commands from audit/debug commands, or add a short docs section that does so. Do not add a new primitive.
