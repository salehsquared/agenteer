# Tick 0160 Challenge - Skeptical Statistician

## Critique

The recent actual-paper work is more honest than fixture-only testing, but it still does not prove that the research platform is doing the most important part of the work. The papers are produced by bespoke Python scripts, then Agenteer audits the aftermath. That is useful chain-of-custody, but it is not yet a spec-governed research runner. A skeptical methods reviewer would say the platform is still a quality gate wrapped around manual analysis, not the author of a reproducible analysis.

The biggest statistical problem is that the generated papers repeatedly use approximate normalized weights and non-design-based model variance. The prose is careful, and `paper-qa` blocks overclaiming, but the platform is normalizing a workaround. If Agenteer keeps generating polished papers before it can run a true survey-aware model, paper QA may train the workflow to become rhetorically safe instead of methodologically correct.

The new `paper-runner-record` and `paper-index` integration is valuable, but the record currently allows retrospective AnalysisSpec binding. That creates a dangerous middle ground: an artifact looks spec-linked even when the spec did not govern execution. Retrospective binding should be allowed for migration, but it should be visibly downgraded everywhere a reviewer might infer reproducibility.

Finally, the actual paper index proves that artifacts exist, not that the analysis question was well-chosen or that alternatives were adjudicated. The platform needs stronger pre-analysis pressure: candidate protocol portfolio, AnalysisSpec-first execution, rejected endpoint rationale, and a clear distinction between "paper passed QA" and "study passed methods review."

## Actionable Implications

1. Make task/evidence envelopes explicit around actual-paper runs so generation, QA, and runner provenance are not hidden in tick prose.
2. Add visible downgrade/warning behavior for retrospective AnalysisSpec binding.
3. Require rejected endpoint or rejected model rationale when a paper's evidence shows alternatives were dropped.
4. Continue generating actual papers, but prioritize papers that expose different methodological stressors over papers that are easy to narrate.
5. Treat complex-survey variance support as the largest methods blocker.

## Evidence That Would Change This Critique

- A paper generated from an AnalysisSpec that existed before execution, with hash binding and no retrospective downgrade.
- A runner adapter that executes a survey-aware model with strata, PSU, and correct cycle/subsample weighting.
- Paper QA that distinguishes reporting completeness from methods adequacy.
- A challenge case where the platform refuses to write a paper because the design or data quality is not sufficient.
