# Tick 173 Challenge - End-User Clinician

## Critique

The current generated papers are technically much better than the early corpus, but a clinician-reader still has to work too hard to separate "review-ready local analysis" from "clinically actionable result." The lifecycle says `ready_for_local_review`, but the paper itself does not have a compact first-read badge that says: survey-aware, cross-sectional, not causal, complete-case, subsample if applicable, and not diagnostic/actionable.

The fasting-glucose paper is a good example. It now correctly discloses `WTSAF2YR` and the fasting subsample, but the result still reads like an association estimate before it reads like a qualified public-health research artifact. A clinician skimming the abstract could anchor on the p value and effect estimate before seeing the population and interpretive limits.

The platform should produce a generated "reader safety header" or "methods badge" before the abstract for machine-generated papers. That header should be concise, boring, and standardized. It should not replace the paper text, but it should stop overinterpretation in the first five seconds.

## Actionable Implications

- Add a standardized local-review header to generated papers, preferably before the abstract.
- Include: `analysis type`, `survey method`, `weight domain`, `population`, `causal status`, `diagnostic/actionability status`, and `human review requirement`.
- Make `paper-qa` require this header for `paper-run` generated papers once implemented.
- Keep it generic enough for non-NHANES public-health datasets.

## Evidence That Would Change This Critique

- A generated paper whose first visible block lets a clinician instantly see scope and limits.
- QA checks that block generated papers missing the first-read safety header.
- A lifecycle summary that matches the paper header so readers do not need to inspect JSON to verify the claim boundary.
