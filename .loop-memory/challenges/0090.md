# Tick 0090 Challenge

Persona: Adversarial security reviewer

## Critique

The enriched real-data artifacts now record absolute file paths and Python executable paths. That is useful locally, but it creates a new export/privacy risk. If a packet is shared, it may leak workstation usernames, repo names, branch context, cache structure, and local environment layout.

This matters because the research pipeline explicitly exports reproducible packets. Reproducibility metadata and shareable metadata are not identical. Internal packets can include absolute paths; exported packets should probably include path role, basename, hash, size, and adapter kind, with absolute paths redacted or moved to a local-only section.

The same concern applies to `variable-map` suggestions and readiness artifacts. They now inherit file paths from `table-summary` and data-access evidence. Without a policy, downstream export may preserve too much local information.

## Actionable Implications

- Add a path-redaction/export policy before treating enriched data-access as share-ready.
- Distinguish `localPath` from `displayPath` or `sourceRef`.
- Make `research export` either redact local absolute paths or warn/block when local paths are present.
- Keep hashes and file basenames visible; they are useful and less sensitive.
- Add this to packet-readiness share posture.

## Evidence That Would Change This Critique

- Exported packet artifacts do not expose `/Users/...` paths by default.
- Internal artifacts retain enough path detail for local reruns.
- Packet readiness warns when local absolute paths make a packet unsuitable for sharing.
