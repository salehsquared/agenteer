# Challenge 0200 - Prediction Posture Is Necessary But Not Sufficient

Persona: skeptical prediction-model reviewer.

## Web-Creativity Inputs

- TRIPOD+AI (BMJ 2024) emphasizes transparent reporting for prediction models using regression or ML and highlights reproducibility, fairness, and open-science expectations: https://www.bmj.com/content/385/bmj-2023-078378
- PROBAST+AI (BMJ 2025) focuses on risk of bias and applicability; the abstracted concern is that impressive model performance can still be biased, overinterpreted, or inapplicable: https://www.bmj.com/content/388/bmj-2024-082505
- scikit-learn calibration docs distinguish calibration/probabilistic reliability from discrimination and describe proper scoring rules such as Brier/log loss: https://scikit-learn.org/stable/modules/calibration.html

## Critique

The new stats and ML `resultPosture` fields are good, but posture is still self-attested by the runner. For prediction modeling, `locally_validated_prediction` is too easy to overread unless the platform also records design-context checks: whether the split is clinically meaningful, whether the target timing avoids leakage, whether calibration was assessed on adequate bins, whether class imbalance makes AUROC misleading, whether subgroups/fairness were even considered, and whether the model is development-only versus externally validated.

The tail-end failure mode is not that Agenteer lacks models. It is that Agenteer can run many models and give them polished postures while missing the harder question: should this predictive task exist in its current form? A random forest with good AUROC on a toy or convenience split can look stronger than a transparent regression with better transportability and clearer clinical failure modes.

## Required Next Response

The next implementation tick should not add another estimator. It should make `modeling-plan` consume prior run posture/evidence and produce a concrete next action such as:

- promote only to local review
- rerun with calibration/fairness/subgroup checks
- compare against simpler baseline
- reject as unsupported task design
- stop for external validation design
- repair executable failure

## Tail-End Idea

Borrow from aviation incident review: every model run should have a black-box recorder summary that captures not only metrics, but why this run is not allowed to make the next stronger claim. Posture should be a gate ladder, not a label.
