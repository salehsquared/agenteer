# Tick 0065 Challenge: Recommended Commands Are A Trust Boundary

Persona: Adversarial security reviewer

## Critique

`packet-readiness.recommendedCommands` is useful, but it is also a trust boundary. Downstream agents may execute these strings. Today they are built from component `nextAction` values, and the filter only keeps strings starting with `agenteer `. That is better than arbitrary prose, but still coarse.

If a future component includes a chained command or a path with shell-sensitive characters, downstream automation may execute more than intended. This is especially relevant because packet paths can come from user-controlled directories.

## Actionable Implications

- Treat `recommendedCommands` as display suggestions, not execution authority, until commands are structured.
- Prefer a structured command object: `{ command: "agenteer", args: [...] }`.
- If keeping strings, avoid shell chains in this field and document that consumers must execute without shell interpolation.
- Consider a narrow helper to admit only single `agenteer research ...` commands.

## Evidence That Would Change This Critique

I would soften the critique if recommended commands were structured argv arrays or were generated by a helper that rejects shell operators.

## Recommended Next Tick

Harden `recommendedCommands`: either structure them, or filter out chained/compound shell strings and document non-shell execution.
