# Tick 0135 Challenge

Persona: Adversarial security reviewer.

Critique: `golden-manifest.json` is useful, but it is still self-attested. The same local script that creates the manifest can mark status `ready_for_local_review`, so the manifest is not yet an independent verifier. It also includes absolute local paths, which is fine for local review but unsafe as a share/export artifact. Hashes help, but a malicious or buggy generation step could hash the wrong files unless a verifier recomputes the expected roles and checks required artifact classes.

Actionable implications:

- Add an independent verifier or integration test that recomputes artifact hashes and readiness checks.
- Separate local-only manifest paths from share-safe manifest paths before export.
- Treat `ready_for_local_review` as local-only; do not imply portability.
- Golden readiness should fail on missing `analysis-spec.json`, source validation not passed, rerun diff not stable, paper QA not pass, missing runner record, or hash mismatch.

What would change this critique: a verifier test intentionally corrupting one golden artifact and proving readiness fails.
