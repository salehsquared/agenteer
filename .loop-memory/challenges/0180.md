# Tick 180 Challenge - New Contributor Fake-Progress Audit

Persona: New contributor.

## Critique

The last few implementation bursts made Agenteer substantially more capable, but a new contributor would struggle to know which surface is the "real" one. `paper-run`, `method-select`, `modeling-plan`, `ml-run`, `ml-compare`, `paper-lifecycle`, `paper-rerun-stability`, and benchmark/manifest commands are individually useful, but the order of use is still mostly encoded in memory and agent behavior.

The new `modeling-plan` primitive improves model-choice visibility, but it currently adds another front door before it proves it can simplify the golden path. It needs table/spec evidence ingestion before it should become a recommended public step.

## Fake-Progress Audit

Recent changes that improved a golden task or outcome-contract risk:

- `paper-run --backend r-survey` improved methods correctness for NHANES survey papers.
- safety headers and paper QA reduced overread/causal overclaim risk.
- rerun-stability checks improved reproducibility pressure.
- `modeling-plan` improves architecture by making model choice inspectable.

Recent changes that added surface area without enough proof:

- `modeling-plan` is currently flag-driven and not yet golden-packet-proven.
- The ML adapter layer is well tested on synthetic data, but not yet integrated into a real packet from AnalysisSpec.
- Public commands now outpace the docs' ability to tell a new contributor where to start.

Most likely wrong assumption:

- That a deterministic heuristic planner is enough to choose modeling strategies. It needs data evidence, backend availability, and prior run outcomes before it can be trusted.

Candidate to remove, merge, or demote:

- Demote `modeling-plan` from "front door" to "experimental decision support" until Tick 181 or the next implementation tick makes it evidence-aware.

## Evidence That Would Change This Critique

- A test where `modeling-plan` consumes a low-N/high-missingness table and a large/clean table and changes its ranking appropriately.
- A golden packet where `modeling-plan` produces the selected method/model family before execution.
- Docs showing the recommended sequence from question -> modeling-plan -> AnalysisSpec/method/ml/paper execution.

## Actionable Implications

1. Add table-summary or table-file ingestion before adding any more model adapters.
2. Split `blockingPolicies` from executable candidates.
3. Make low-N/high-missingness data downgrade high-capacity ML.
4. Add CLI smoke output that proves data evidence changes the plan.
5. Update docs so a new contributor sees one research modeling path instead of isolated commands.

## Counter-Design Rejected

I reject treating the current command list as self-documenting. The larger Agenteer gets, the more the golden path must be encoded in commands, tests, and docs rather than remembered by the orchestrating agent.
