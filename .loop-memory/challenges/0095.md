# Tick 0095 Challenge

Persona: Methodology archivist

## Critique

`data-access-redact` creates a safer derived artifact, but the archive story is still incomplete. The command proves that a redacted view can exist; it does not prove that a packet export used the redacted artifact instead of raw `data-access.json`, nor that the exported package can be inspected later to confirm no local-path leakage occurred.

This is a methodological archiving issue, not only a security issue. A reproducible research packet needs a durable boundary between local rerun metadata and shareable provenance. Right now that boundary depends on a user or orchestrating agent remembering to run a separate command and prefer the right artifact. That is too fragile for an indefinite dogfood loop.

The redacted artifact also has no explicit relationship to the raw manifest beyond naming convention. A reviewer can see file hashes and source refs, but cannot verify that `data-access-redacted.json` was generated from a specific `data-access.json` unless they trust the surrounding filesystem state. For archive-grade provenance, the redacted view should carry a source manifest hash or derivation record that does not disclose the source path.

## Actionable Implications

- `research export` should either substitute `data-access-redacted.json` for raw `data-access.json` or include both with a clear local-only/private designation.
- `packet-readiness` should distinguish "redaction artifact exists" from "export will use redaction artifact."
- `data-access-redacted.json` should include a source manifest SHA-256 and generated-at timestamp so it is a derived evidence artifact, not just another JSON file.
- Export verification should include a no-absolute-local-path scan over shareable artifacts.

## Evidence That Would Change This Critique

- An exported packet tarball or directory that includes `data-access-redacted.json`, excludes or quarantines raw local-path manifests, and passes an automated local-path scan.
- A manifest entry showing `data-access-redacted.json` was derived from a specific source manifest hash.
- A packet-readiness result that changes share posture when the redacted artifact is missing, stale, or not referenced by export metadata.
