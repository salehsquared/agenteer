# Tick 0395 Challenge: Methodology Archivist Review

Persona: Methodology archivist

## Critique

The validation corpus is proving execution breadth, but it still does not prove that the platform chooses the right method for a real study or that every method's assumptions are adequately checked. A method can be implemented correctly at the API level while still being scientifically inappropriate for a given question.

Specific concerns:

- Many routes have `stats-qa` warnings because route-specific assumption checks remain shallow.
- Survival routes run but do not yet include proportional-hazards diagnostics such as Schoenfeld-style checks.
- Quasi-experimental routes run but mostly encode design-review boundaries; they do not prove parallel trends, exclusion restrictions, or causal exchangeability.
- Penalized models correctly warn about inference caveats, but the downstream report path could still overread coefficients if not guarded.
- The validation dataset is synthetic, so it exercises mechanics more than messy real-data pathologies.

## Actionable Implications

- The final validation index must separate "execution validated" from "methods assumptions validated."
- Prediction, missingness, diagnostics, reliability, PCA, clustering, and figure routes still need explicit validation.
- The suite needs a negative-control / blocked-method row so unavailable backends remain visible.
- Future work should add method-specific assumption QA rather than only broad `stats-qa` warnings.

## Evidence That Would Change This Critique

This critique would soften if the validation index records status, QA status, figure count, paper/manuscript availability, typed issues, and a conservative readiness category for every executed route, followed by targeted tests passing.
