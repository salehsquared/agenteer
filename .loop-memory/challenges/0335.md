# Tick 0335 Challenge - Stroke Packet Prediction-Language Review

Persona: Skeptical statistician.

## Critique

The stroke packet is a useful real neurology analysis, but the language still drifts toward prediction while the validation evidence is association-style and internally assessed only. AUROC is reported, and the question says "predict mortality," but the packet does not have train/test split evidence, calibration, temporal validation, or external validation. The manuscript now says internal prediction evidence, which is better than a deployment claim, but the study still needs a clearer route decision: is this a risk-marker association paper or a prediction-model evaluation?

The trust layer correctly flags missing separation, collinearity, and influence diagnostics. It does not yet separately warn that prediction wording requires calibration/validation evidence. This matters because the report can pass manuscript QA while still being statistically under-specified for a prediction claim.

## Actionable Implications

- Treat the current stroke packet as local observational/risk-marker evidence, not a prediction model paper.
- Add a future QA rule: if the question or manuscript uses prediction framing and AUROC/AUPRC, require calibration and validation-design evidence or downgrade the prediction claim.
- Add phenotype sensitivity for ICD-9 `434` subcodes because not all subcodes are equally explicit about infarction.

## Evidence That Would Change This Critique

The critique would soften if the packet included a validation split or temporal validation, calibration plot/slope/intercept, prespecified prediction horizon, intended use/non-use statement, and sensitivity excluding ambiguous ICD-9 occlusion-without-infarction codes.
