# Tick 0115 Challenge

Persona: Skeptical statistician.

Critique: `research paper-qa` is now useful as a reporting gate, but it can still be fooled by well-written but weak analysis. It verifies sections, caveats, citations, row counts, and some threshold language; it does not yet check whether the model class matches the endpoint, whether the reported effect estimate matches the model family, whether covariate adjustment is stated and stored consistently, whether weighted estimates are clearly approximate versus design-correct variance, or whether evidence JSON contains enough model diagnostics to support the Results prose.

Actionable implications:

- Paper QA should include model-family checks: logistic models should report odds ratios or prevalence ratios, linear models should report mean differences/regression coefficients, and threshold classifiers should identify binary outcome construction.
- Evidence JSON should expose `model.family`, `effectMeasure`, `covariates`, `weighting`, and `varianceMethod` so QA can compare the paper against the analysis object.
- QA should warn when the evidence says `approximate` weighting or non-design-correct variance but the paper presents narrow confidence intervals without a corresponding limitation.
- Paper generation should eventually include a model audit block before prose generation, not only after-the-fact QA.

What would change this critique: three different paper types passing a model-aware QA gate that catches at least one intentionally mismatched paper/evidence fixture.
