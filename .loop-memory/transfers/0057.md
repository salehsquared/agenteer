# Tick 0057 Cross-Domain Transfer

## Open Question

How should `packet-readiness` distinguish "safe to read internally" from "safe to export/share" while remaining actionable?

## Fields Searched

- Air traffic control: read-back/hear-back.
- Compilers: dominator/control-flow analysis.
- Lean manufacturing: Andon / stop-the-line authority.

## Techniques Considered

- Read-back/hear-back: require an explicit repeated clearance before proceeding.
- Dominator tree: find the prerequisite node that dominates every path to a safe decision.
- Andon cord: make stop conditions visible and actionable when quality is blocked.

## Chosen Citation

Lean Enterprise Institute, Andon: https://www.lean.org/lexicon-terms/andon/

## Structural Mapping

- Production line = research packet moving toward sharing/export.
- Andon stop = `decisionPosture: stop`.
- Station problem = blocking/missing reason in readiness components.
- Team response = next action and repair command.

## Required Architecture Change

`packet-readiness` needs explicit stop reasons, not only a stop posture.

## Smallest Trial

Added `stopReasons: string[]` to `ResearchPacketReadiness` and the renderer.
