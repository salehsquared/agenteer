# Tick 0133 Cross-Domain Transfer

Open question: how should the golden packet prove rerun stability before more features are added?

Fields considered:

- Control theory: compare system output after applying the same input and controller; drift indicates instability.
- Compilers / programming language theory: deterministic build artifacts compare bit-for-bit or through exact expected outputs.
- Cryptography: hash commitments bind inputs and outputs, but hashes alone do not prove semantic equivalence.

Chosen technique: deterministic build comparison from compilers.

Structural mapping:

- `AnalysisSpec` is the build recipe.
- Source Parquet inputs are source files.
- `rerun-analysis.json` is the build artifact.
- `rerun-diff.json` is the deterministic build comparison report.

Required architecture change: golden runs should write an explicit rerun diff artifact before they are treated as stable.

Smallest trial: reran the insurance/HbA1c model from the golden `analysis-spec.json` and compared model estimates, CIs, p values, and sensitivity-model values to the original `analysis.json`.

Status: implemented as a golden artifact. The rerun diff is `stable` with zero numeric diffs at tolerance `1e-12`.
