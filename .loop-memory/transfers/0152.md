# Tick 0152 Cross-Domain Transfer

Open question: how should runner records prove they executed the current AnalysisSpec rather than a stale protocol?

Fields considered:

- Cryptography: certificate chains bind identity to keys through signed hashes.
- Compilers: build systems invalidate outputs when dependency hashes change.
- Air traffic control: clearances are only valid for a specific filed flight plan.

Chosen technique: cryptographic certificate-chain style binding.

Structural mapping:

- AnalysisSpec = certificate subject / contract.
- Runner record = execution certificate.
- Manifest verification = chain validation.
- Spec hash mismatch = stale or invalid certificate.

Architecture change:

`research manifest-verify` should compare the `analysis-spec.json` hash declared inside the runner record with the current AnalysisSpec's `specHash` whenever both artifacts are present.

Smallest trial:

Add `analysisSpec.specHash` to the golden runner record and make manifest verification fail if it does not match.

Status: implemented in Tick 0152.
