# Tick 0126 Capability Rave

## Ten Fast-Malleable Items

1. Add `runner-record.json` to every generated paper directory.
2. Add runner status to `research paper-index`.
3. Add `research paper-runner-record --paper-dir` to verify input/output hashes.
4. Generate papers from a reusable local runner template instead of heredocs.
5. Require a runner record before `paper-index` reports a paper as reproducible.
6. Add a `varianceMethod` field to all paper evidence JSON.
7. Add package versions and Python path to `analysis.json`.
8. Emit one `run.sh` per paper for approximate local rerun.
9. Add a paper corpus QA command that checks all paper dirs at once.
10. Add a paper critique rubric command that normalizes free-form critiques.

## Ten Looks-Fixed-But-Is-Not Items

1. Paper directories look complete but lack run provenance except Paper 4.
2. QA status passes but does not prove the paper can be regenerated.
3. Input Parquet paths are mentioned but not hash-bound in most paper directories.
4. Dependency versions are implicit.
5. Approximate variance is disclosed, but not machine-enforced as a method field everywhere.
6. Web sources are cited in papers, but source-intake artifacts are not linked into each paper directory.
7. The paper index lists QA but not runner status.
8. Critiques are useful but not rubric-comparable.
9. Scripts are not saved, so rerunability depends on tick history.
10. No paper currently has full design-correct NHANES survey variance.

## Gaps That Should Be Malleable But Are Not

- A reusable paper-generation runner does not exist yet.
- Paper directories do not have a required manifest schema.
- The CLI cannot yet distinguish "QA-passing paper" from "reproducibly generated paper."

## Web-Grounded Shape

Workflow Run RO-Crate and Process Run Crate motivate recording inputs, outputs, commands/tools, runtime, and action status. Ten Simple Rules for Reproducible Computational Research similarly argues that every result should keep track of how it was produced and avoid manual data manipulation when possible.
