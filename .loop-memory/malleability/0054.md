# Tick 0054 Capability Rave

## Ten Fast-Malleable Items

- `RESEARCH_STAGE_ARTIFACTS`: can expose or validate stage artifact names; unlocks drift detection.
- `researchQaDashboardCommand`: can consume shared stage artifacts; unlocks unified readiness semantics.
- `researchPacketReadinessCommand`: can consume QA checks instead of duplicating them; unlocks lower maintenance.
- `ResearchPacketReadinessComponent`: can carry source command names; unlocks guided repair.
- `renderResearchPacketReadiness`: can reorder by severity; unlocks faster human triage.
- `researchStageArtifactsCommand`: can become the read-only source for docs; unlocks generated CLI docs.
- `researchPacketSummaryCommand`: can include readiness posture; unlocks single-screen status.
- `commandForResearchStage`: can be exported internally; unlocks consistent next-action language.
- `researchManifestVerifyCommand`: can consume stage artifacts; unlocks stage-aware manifest checks.
- `qa-dashboard.json`: can carry schema version; unlocks safer downstream parsing.

## Ten Looks-Fixed-But-Is-Not Items

- Stage order looks fixed, but stage metadata can be projected into docs, tests, and readiness.
- Provenance filename looked fixed, but was stale in one registry and current elsewhere.
- Readiness status looks binary, but decision and share postures can vary independently.
- Report review looks packet-local, but claim guard can be used as an inline component.
- Checkpoint looks like the lifecycle source, but it only sees artifact presence.
- Packet summary looks human-facing, but readiness now has the better decision wording.
- Manifest verification looks purely hash-based, but it can become stage-aware.
- CLI help looks hand-written, but stage and artifact sections could be generated.
- Test runner looks blocked, but build plus CLI smoke and type-level tests still catch many errors.
- MedBrevia looks read-only, but its analytics workflow can keep supplying contracts and failure modes.

## Gaps That Should Be Malleable But Are Not

- Readiness, QA, and checkpoint still build overlapping projections manually.
- There is no central severity mapping from artifact/component status to decision posture.
- The CLI help is too large to inspect quickly and is not subcommand-scoped.

## Picked Item

Implemented drift coverage for the provenance artifact across `stage-artifacts`, `qa-dashboard`, and `packet-readiness`.
