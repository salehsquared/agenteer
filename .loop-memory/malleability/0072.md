# Tick 0072 Capability Rave

## Ten Fast-Malleable Items

- `packet-readiness`: can expose the implicit profile id.
- `references`: can be profile-specific.
- `limitations`: can be profile-specific.
- `components`: can later be generated by profile policy.
- `decisionPosture`: can be profile-scoped.
- `sharePosture`: can be profile-scoped.
- Docs JSON contract: can name the profile as stable.
- Tests: can assert the default profile without needing selection.
- Export: can preserve profile information in `packet-readiness.json`.
- Future domains: can add profiles without changing current output.

## Ten Looks-Fixed-But-Is-Not Items

- STROBE looks hardcoded but is actually a profile reference.
- Survey caveats look global but should belong to observational-survey profile.
- Readiness mode looks enough, but profile id is the real domain boundary.
- Component policy looks procedural but can become data.
- Profile selection looks required but can wait.
- Medical defaults look general but are not.
- JSON contract looks flat but can carry policy metadata.
- Report review looks universal but should vary by domain.
- Claim guard looks universal but causal-language policy is domain/design specific.
- Export looks profile-agnostic but should preserve the profile used.

## Gaps That Should Be Malleable But Are Not

- No profile selection mechanism.
- No profile registry.
- No profile-specific component policy.

## Picked Item

Added a minimal default `readinessProfile` object to `packet-readiness`.
