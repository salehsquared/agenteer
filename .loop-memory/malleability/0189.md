## Ten Looks-Fixed-But-Is-Not Items

1. Method ontology looks comprehensive, but many entries are design-only. Executability needs explicit mapping.
2. `stats-run` looks bound, but lifecycle does not yet consume its binding.
3. Survey refusal looks safe, but AnalysisSpec-derived survey fields are not auto-read by stats-run.
4. Logistic diagnostics look typed, but separation detection is coefficient-threshold based.
5. Poisson diagnostics warn overdispersion, but negative binomial is not executable yet.
6. Calibration exists for ML, but decision curves/net benefit do not.
7. ML compare ranks models, but does not include statistical baselines in the same comparison.
8. `modeling-plan` names stats-run, but does not create the selection file itself.
9. Artifact hashes exist, but there is no stats-run rerun-stability command.
10. Docs warn about survey boundaries, but no paper QA consumes stats issues yet.

## Gaps That Should Be Malleable

- A single method-to-runner registry should drive modeling hints, binding validation, execution contracts, and docs.
- Stats, ML, and survey runners should eventually share artifact/binding/issue envelopes.
- A golden standard-table paper should pressure this path separately from NHANES survey papers.
