# Tick 0144 Capability Rave

## Fast-Malleable Items

1. `golden-packet.json`: status can reflect current verified reality instead of stale candidate wording.
2. `analysis-spec.json`: can carry failure policy, not just model inputs.
3. `golden-manifest.json`: can be the single local-review readiness contract.
4. `researchRepairPlanCommand`: can consume more typed verifier sources.
5. `researchManifestVerifyCommand`: can keep adding typed issue codes without CLI growth.
6. `paper-index`: can rank papers by reproducibility completeness.
7. `runner-record.json`: can become an AnalysisSpec execution receipt.
8. `source-validation.json`: can be promoted into a generated preflight result.
9. `rerun-diff.json`: can define instability thresholds by metric.
10. `share-safety.json`: can become an export gate rather than a note.

## Looks Fixed But Is Not

1. `AnalysisSpec` looks typed, but the golden run was generated before the spec existed; future runs need spec-first receipts.
2. `manifest-verify` looks like reproducibility, but it verifies bytes and readiness fields, not method correctness.
3. `paper-qa` looks strict, but cannot judge omitted confounding by itself.
4. `runner-record` looks reproducible, but old records were backfilled retrospectively.
5. `data-access-redact` looks share-safe, but export still needs redacted substitution by policy.
6. `packet-readiness` looks broad, but the golden packet is currently validated more by direct artifacts than that command.
7. `repair-plan` looks actionable, but it still proposes actions rather than applying bounded patches.
8. `cohort-scout-file` looks survey-aware, but Parquet-backed scouting remains external.
9. `semantic-quality` looks general, but clinical rule registries are still small.
10. `golden-manifest` looks canonical, but it is handwritten rather than generated.

## Gaps That Should Be Malleable

- AnalysisSpec should contain failure policy and rerun thresholds.
- Runner records should cite the exact AnalysisSpec hash used for execution.
- Golden packet status should be automatically derivable from verification outputs.
- Repair plans should group executable failures separately from methodological blockers.

## Chosen Move

Update the stale golden packet status now. It is low-risk, removes misleading state, and keeps the golden packet aligned with the verification evidence already produced.
