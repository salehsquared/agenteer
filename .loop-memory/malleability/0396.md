# Tick 0396 Capability Rave: Stats Runner As A Validation Spine

## Ten Fast-Malleable Items

1. `stats-run.json`: add validation-index ingestion from existing fields.
2. `figures.json`: promote visual artifact count into validation scoring.
3. `stats-qa.json`: use warning/fail status as review category input.
4. `paper.md`: available for diagnostic and propensity routes as reader-facing proof.
5. `manuscript.md`: can wrap generic stats routes without new generators.
6. `analysis-run-manifest.json`: can distinguish readiness from artifact completeness.
7. `issues[]`: already typed enough to separate caveats from blockers.
8. `resultPosture`: already carries interpretation boundaries.
9. Method-specific CSVs: curves, balance, imputations, PCA outputs can prove side effects.
10. Existing Vitest suite: can absorb regression coverage from validation failures.

## Ten Looks-Fixed-But-Is-Not Items

1. "Succeeded" does not mean assumptions are checked.
2. `stats-qa` warnings are too generic for several method families.
3. Survival routes lack PH assumption diagnostics.
4. Quasi-experimental routes lack real design proof.
5. Penalized models run but need stronger report-level caveat propagation.
6. Some methods naturally lack figures; figure absence must not be a false failure.
7. Synthetic validation is not messy real-data validation.
8. Paper generation is route-specific, not universal.
9. Backend blockers are honest but need one consolidated index.
10. Multiple comparison and power outputs are useful but not tied into planning gates yet.

## Gap To Implement

Build a validation index that reads all run directories and classifies each route as executable, review-limited, or backend-blocked, with figure count and reader-artifact availability.
