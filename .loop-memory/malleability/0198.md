# Malleability 0198 - result posture is more malleable than it looks

## Ten Fast-Malleable Items

1. `StatsRunResult`: add result posture without a new command.
2. `stats-report.md`: surface posture in the local review safety header.
3. `stats-qa.json`: include posture checks as deterministic QA.
4. `paper-lifecycle`: show stats posture beside status/method/binding.
5. `modeling-plan`: use posture later as prior run evidence.
6. `MlRunResult`: mirror result posture for prediction outputs later.
7. `paper-index`: eventually show stats/ML posture across packets.
8. `repair-plan`: consume failed/blocked posture codes.
9. `golden benchmark`: score posture correctness.
10. `docs/research-ml.md`: teach route posture, not only commands.

## Ten Looks-Fixed-But-Is-Not Items

1. `status=succeeded`: computation succeeded, but interpretation may be exploratory.
2. `binding=unbound`: currently a detail, but should change posture.
3. `--allow-survey-approximation`: a flag, but really a methods boundary.
4. `stats-report.md`: deterministic text can still carry structured posture.
5. `lifecycleStatus`: paper-level status can include runner-family posture.
6. `modeling-plan.routeRecommendation`: can later incorporate prior run posture.
7. `stats-qa.json`: can check interpretation, not just files.
8. `warnings`: can be summarized into reviewer-ready posture.
9. `artifacts`: can expose meaning, not only existence.
10. `ML metrics`: can later separate prediction performance from clinical actionability.

## Gaps That Should Be Malleable

- ML result posture is not yet implemented.
- Stats task/evidence envelopes are not generated automatically.
- Prior run posture is not consumed by route recommendations yet.

## Selected Implementation

Add `resultPosture` to `StatsRunResult` and lifecycle output.
